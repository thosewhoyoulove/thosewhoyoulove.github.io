# MCP 与工具调用概念

## 面试定位

面试官问 MCP 或 Function Calling，通常想确认两件事：你是否分得清**模型侧工具调用**与**协议化工具接入**；以及前端如何展示权限、进度和结果。字段名以各厂商文档为准，这里讲稳定概念。

## 面试回答

可以这样答：

> Tool Calling 的本质是模型产生结构化的调用意图，真正的参数校验、授权、执行和结果回传都由宿主运行时完成。MCP 解决的是能力接入标准化：Host 通过 Client 与一个或多个 Server 建立会话，协商能力并发现 tools、resources、prompts，而不是让每个 Agent 为每个数据源重写私有适配。三类能力的控制方式不同：Tool 通常由模型选择调用，Resource 由应用选择如何纳入上下文，Prompt 更偏用户显式选择的模板。MCP 只规定交互协议，不替代 OAuth、业务鉴权和审计；即便用户连接了 Server，每次工具执行仍要按当前用户、资源和参数做最小权限校验。前端负责连接授权、能力清单、运行状态和高风险确认，但绝不是权限真相来源。

一句话总结：

> Tool Calling 让模型“会点工具”；MCP 让工具“可被标准方式发现与接入”。

---

## 核心原理

```text
模型推理
  → 产生 tool call（名称 + 参数）
  → 宿主/运行时校验权限并执行
  → 得到 tool result
  → 写回对话上下文
  → 模型继续生成或再次调用
```

MCP 视角（概念级）：

```text
Host（IDE / Agent 应用）
  ↔ MCP Client
  ↔ MCP Server（暴露 tools / resources / prompts）
```

具体消息字段以官方 MCP 与模型文档为准。

## 1. Function Calling 解决什么

没有工具时，模型只能“说”。有工具后，模型可以：

- 查实时数据（文档检索、工单状态）
- 执行动作（创建资源、跑检查脚本）
- 把不确定问题转成可验证的外部结果

| 角色 | 职责 |
| --- | --- |
| 模型 | 决定是否调用、选哪个工具、填参数 |
| 运行时 | 鉴权、执行、超时、审计 |
| 前端 | 展示意图与结果，必要时拦截确认 |

**要点**：模型“提议调用” ≠ 已经执行成功；UI 必须区分这两种状态。

## 2. MCP 在产品里的位置

可以把 MCP 理解成“给 Agent 用的插件协议”：

| 能力类型（概念） | 用户感知 |
| --- | --- |
| Tools | 可执行动作，有参数与结果 |
| Resources | 可读上下文（文件、文档片段） |
| Prompts | 预置提示模板 |

对前端/客户端的价值：

- **发现**：列出当前可用服务器与工具，而不是写死。
- **描述**：名称、说明、参数 schema 驱动表单或折叠 JSON。
- **权限**：连接哪些 server、允许哪些 tool，要有显式授权 UX。

**不适用**：把它讲成“替代 LLM”或“替代业务后端”。MCP 是接入层，业务真相仍在你们的 API 与权限体系。

还要区分“发现能力”和“有权执行”。工具列表动态变化后，Host 应刷新能力缓存；连接授权只说明客户端可以访问该 Server，不代表模型可无限调用所有工具。远程 HTTP Server 通常结合标准授权流程；本地 stdio Server 则由宿主控制进程与凭证边界。无论哪种传输，都不应把上游 Token 原样透传给下游服务。

## 3. 前端面试常答的落点

1. 工具卡片：名称、摘要参数、展开原始 JSON。
2. 状态机：`proposed` → `awaiting_approval?` → `running` → `success | error | cancelled`。
3. HITL：写操作、删数据、对外发送，默认要确认。
4. 错误：超时、无权限、参数非法，文案可行动（重试/改参数/联系管理员）。
5. 与流式并存：文本 delta 和 tool 事件交错到达，按 event 类型路由，而不是假设“先全文后工具”。

**场景（示例）**：开发者控制台 Agent 调用“重启实例”工具前，前端展示实例 ID 与影响面，用户确认后才把 approve 事件发给 BFF。

**验证**：工具成功率、平均确认耗时、无权限调用被拒次数、误操作工单数。

## 高频追问

### MCP 和普通 OpenAPI 集成有什么差别？

OpenAPI 是给开发者集成 HTTP 服务；MCP 更强调在 Agent/宿主场景下的动态发现、会话内调用与资源暴露。很多团队两者并存：业务仍是 API，Agent 侧用 MCP 或内部 Tool 适配层封装。

### 为什么工具执行不能只放在浏览器？

浏览器不可信：用户可篡改请求。密钥、高权限操作、审计日志应在服务端或受控运行时完成。

### 工具结果要不要完整展示给用户？

默认展示摘要；完整 JSON 可折叠。含密钥、PII 的结果要脱敏，详见 [安全与合规（前端）](/md/Agent/安全与合规（前端）.md)。
