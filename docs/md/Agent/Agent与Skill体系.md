# Agent 与 Skill 体系

## 面试定位

岗位 JD 常写“参与构建 AI Agent / Skills 体系”。面试官想确认你懂：**Agent 不是单次 Chat，而是带工具的闭环；Skill 是可复用能力沉淀，用来提效而不是每次重写 Prompt**。

## 面试回答

可以这样答：

> Agent 不是“会聊天的模型”，而是由模型决策、工具执行和运行时控制组成的闭环：运行时提供目标、状态与可用能力，模型决定下一步，工具返回可验证的观察结果，再继续、请求人工介入或结束。规划不是每次都必须先生成一份长计划，关键是每一步都有受控输入输出。因为 Agent 会改变外部状态，运行时必须限制最大步数、时间、Token、成本和工具权限，检测重复调用，并为写操作设置审批与幂等。Skill 是可复用的任务级能力包，除了 Prompt，还应包含适用边界、输入输出契约、允许的工具、失败策略、Eval、版本和负责人。稳定业务路径用确定性工作流兜住，只把需要判断和探索的节点交给 Agent。

一句话总结：

> Agent = 规划 + 工具调用闭环；Skill = 可复用、带权限边界的能力单元。

---

## 核心原理

典型 Agent 循环：

```text
用户目标
  → 规划（拆步骤 / 选 Skill）
  → 调用工具或执行 Skill
  → 观察结果（成功 / 失败 / 需更多信息）
  → 更新上下文
  → 继续循环，或结束 / 请求人工确认
```

运行时还要包住四类护栏：

```text
预算：maxSteps / timeout / token / cost
权限：tool allowlist / scope / approval
可靠性：retry / idempotency / repeated-call detection
终止：success / blocked / failed / cancelled
```

## 1. Agent 解决什么问题

| 形态 | 能力 | 局限 |
| --- | --- | --- |
| 单轮补全 | 生成文本/代码片段 | 无外部事实与动作 |
| Chatbot | 多轮对话 | 难可靠改系统状态 |
| Agent | 规划 + 工具 + 观察 | 成本、延迟、失控风险更高 |

Agent 适合：需要多步推理、查资料、调用内部 API、跨系统操作的任务。

不适合：强实时、强一致、必须 100% 正确且无人工兜底的交易路径——这类应走确定性工作流，Agent 只做辅助。

**要点**：先判断任务是否需要“行动”，再决定上不上 Agent。

## 2. Skill 体系怎么理解

可以把 Skill 看成团队级的“能力目录项”：

```text
Skill
  ├── 名称与一句话描述（给模型/人发现）
  ├── 适用场景与不适用场景
  ├── 输入 / 输出约定
  ├── 允许使用的工具与权限
  ├── 示例与失败处理
  ├── Eval 与验收样本
  └── 版本、变更记录与负责人
```

和 Prompt 的关系：

- Prompt：一次对话里的指令。
- Skill：沉淀后的能力包，可被 Agent 选择，也可被人在 IDE/工作流里显式调用。

和岗位“提效”的关系：

- 研发侧：Code Review、生成测试、排查日志等流程 Skill 化。
- 对客侧：文档问答、开通引导、故障诊断等业务 Skill 化。
- 前端价值：做 Skill 的发现、权限提示、执行进度与结果展示。

**要点**：Skill 的核心不是文件格式叫什么，而是**可发现、可复用、可鉴权、可评测、可观测**。Skill 被加载后也不能扩大当前用户本来没有的权限；若多个 Skill 指令冲突，必须服从宿主定义的指令优先级与安全策略。

## 3. 前端在 Agent / Skill 里做什么

| 职责 | 具体表现 |
| --- | --- |
| 过程可见 | 展示当前步骤、正在调用的 Skill/工具 |
| 人机协同 | 高风险步骤 approve / reject / edit |
| 失败可恢复 | 展示错误、支持重试、保留已完成步骤 |
| 能力治理 | Skill 列表、描述、权限说明、禁用态 |

**场景（示例）**：内部运营 Agent 执行“批量导出客户名单”前，前端弹出确认，展示将调用的 API 与数据范围；拒绝则不发执行事件。

**验证**：任务完成率、平均工具轮次、人工介入率、危险操作误执行率（应为 0）。

## 高频追问

### Agent 会不会无限循环？

会，如果没有最大步数、超时、重复检测和终止策略。产品上要展示“已达步数上限”，并允许用户接管。

### Workflow 和 Agent 怎么选？

步骤固定、对正确性要求极高 → 确定性工作流；步骤依赖模型判断、工具结果多变 → Agent。很多系统是混合：关键路径工作流，边缘探索交给 Agent。

### Skill 和 MCP Tool 有什么区别？

Tool 更偏原子能力（一次 API/一次命令）；Skill 更偏任务级能力包，可能组合多个工具与约束。概念上 Skill 在上层，Tool 在下层。
