# Agent 与 Skill 体系

## 面试回答

> 我会从行动闭环、可复用方法和运行约束三个层面理解 Agent。
>
> 首先，**Agent 通过工具结果不断调整下一步行动**。运行时提供目标和状态，模型提议下一步，工具返回观察结果，再决定继续、请求人工介入或结束。规划不一定要先写一份长计划，关键是每一步都能获得可验证的反馈。
>
> 第二，**Skill 把完成一类任务的方法和资源沉淀下来**。Agent 可以根据任务选择 Skill，按需读取规范、参考资料或运行脚本。团队还应维护版本、负责人和验收样本，避免每次从一份临时 Prompt 重新开始。
>
> 第三，**Harness 是承载 Agent 的执行与反馈系统**。它控制状态流转、工具权限、超时、重试、预算和结果校验。若流程规定必须先检索、再草拟、再校验，我会把阶段门禁写入状态机，让模型在允许的步骤内做判断。
>
> **Agent 不等于自由循环，也不等于所有步骤都交给模型**。稳定路径优先用确定性工作流，需要探索和判断的节点再引入 Agent。

一句话总结：

> Agent = 规划 + 工具调用闭环；Skill = 可复用、带权限边界的能力单元。

---

## 核心原理

典型 Agent 循环：

```text
用户目标
  → 规划（拆步骤 / 选 Skill）
  → 调用工具或执行 Skill
  → 观察结果（成功 / 失败 / 需更多信息）
  → 更新上下文
  → 继续循环，或结束 / 请求人工确认
```

运行时还要包住四类护栏：

```text
预算：maxSteps / timeout / token / cost
权限：tool allowlist / scope / approval
可靠性：retry / idempotency / repeated-call detection
终止：success / blocked / failed / cancelled
```

## 1. Agent 解决什么问题

| 形态 | 能力 | 局限 |
| --- | --- | --- |
| 单轮补全 | 生成文本/代码片段 | 无外部事实与动作 |
| Chatbot | 多轮对话 | 难可靠改系统状态 |
| Agent | 规划 + 工具 + 观察 | 成本、延迟、失控风险更高 |

Agent 适合：需要多步推理、查资料、调用内部 API、跨系统操作的任务。

不适合：强实时、强一致、必须 100% 正确且无人工兜底的交易路径——这类应走确定性工作流，Agent 只做辅助。

**要点**：先判断任务是否需要“行动”，再决定上不上 Agent。

## 2. Skill 体系怎么理解

可以把 Skill 看成团队级的“能力目录项”：

```text
Skill
  ├── 名称与一句话描述（给模型/人发现）
  ├── 适用场景与不适用场景
  ├── 输入 / 输出约定
  ├── 允许使用的工具与权限
  ├── 示例与失败处理
  ├── Eval 与验收样本
  └── 版本、变更记录与负责人
```

和 Prompt 的关系：

- Prompt：一次对话里的指令。
- Skill：沉淀后的能力包，可被 Agent 选择，也可被人在 IDE/工作流里显式调用。

和岗位“提效”的关系：

- 研发侧：Code Review、生成测试、排查日志等流程 Skill 化。
- 对客侧：文档问答、开通引导、故障诊断等业务 Skill 化。
- 前端价值：做 Skill 的发现、权限提示、执行进度与结果展示。

**要点**：Skill 的核心不是文件格式叫什么，而是**可发现、可复用、可鉴权、可评测、可观测**。Skill 被加载后也不能扩大当前用户本来没有的权限；若多个 Skill 指令冲突，必须服从宿主定义的指令优先级与安全策略。

---

## 3. 前端在 Agent / Skill 里做什么

| 职责 | 具体表现 |
| --- | --- |
| 过程可见 | 展示当前步骤、正在调用的 Skill/工具 |
| 人机协同 | 高风险步骤 approve / reject / edit |
| 失败可恢复 | 展示错误、支持重试、保留已完成步骤 |
| 能力治理 | Skill 列表、描述、权限说明、禁用态 |

**场景（示例）**：内部运营 Agent 执行“批量导出客户名单”前，前端弹出确认，展示将调用的 API 与数据范围；拒绝则不发执行事件。

**验证**：任务完成率、平均工具轮次、人工介入率、危险操作误执行率（应为 0）。

## 4. Harness 怎样让 Agent 按指定流程执行

给 Prompt 写“务必先检索再作答”可以影响模型选择，但无法阻止它直接输出。若流程顺序属于必须遵守的业务规则，就要由运行时检查当前状态允许什么动作。

```text
received → retrieve → draft → validate → completed
                 ↑             │
                 └─ 补充证据 ───┘
任一步 → failed / cancelled
```

这是一个教学状态机。检索阶段只能使用获授权的数据源；证据不足时返回补充信息需求，不进入草拟。草拟阶段只生成带引用的候选文本。校验阶段检查引用、格式和事实约束，失败则在有限次数内返回修订。是否进入完成状态由验收器决定，不能只凭模型说“完成”。

| 当前状态 | 模型可以建议 | 运行时实际检查 | 转移条件 |
| --- | --- | --- | --- |
| retrieve | 改写查询、选择检索源 | 数据源权限、查询参数、预算 | 获得足够证据或明确失败 |
| draft | 组织结论与引用 | 来源 ID 必须来自本次证据集合 | 生成可解析草稿 |
| validate | 提交修订建议 | 引用有效性、任务验收、重试次数 | 通过后完成，否则有限回退 |

例如用户要求“查故障原因并生成报告”。第一次检索超时，运行时记录错误并按策略重试；第二次得到两条日志，保存证据 ID 后进入草拟；草稿引用了不存在的第三条日志，校验器拒绝；模型修订后再次校验，通过才输出报告。这个循环的有效性来自状态和证据约束，而不是要求模型自己承诺不出错。

任务状态至少保存 `runId`、当前阶段、产物引用、已用预算、尝试次数和结束原因。它们分别用于关联执行、恢复进度、避免重复传递大结果、控制循环和解释失败。若进程重启，持久化状态能支持恢复；涉及外部写入时，还要记录业务幂等键并查询实际执行结果，不能把恢复简单理解成重放所有动作。

权限、预算和验收是三类不同门禁。已授权的工具仍可能因为预算耗尽而停止；在预算内完成的工具调用也可能没有满足任务验收。审批只放在用户授权和产品策略需要的步骤，低风险读取可直接继续，不能把每一步都变成人工点按钮。

Harness 的效果用任务成功率、违规调用率、平均耗时、Token 成本和恢复成功率评估。Skill、工具或模型版本变化后，用固定任务集回归，检查是否出现“步骤都成功，最终目标却未达到”。这里描述通用 Agent 工程方法，不推断某个产品的内部实现。

## 5. 对话之外还有哪些 Agent 形态

对话是输入和展示方式，Agent 的核心仍是目标、工具、观察和受控执行。相同运行时可以由不同事件触发：

| 形态 | 触发方式 | 产物与交互 |
| --- | --- | --- |
| 后台任务 Agent | 用户提交任务后异步执行 | 任务页、进度、报告、失败恢复 |
| 事件驱动 Agent | 新工单、告警、Webhook | 调查结果、处理建议、受控动作 |
| 定时 Agent | 周期计划 | 巡检、摘要、到期提醒 |
| 嵌入式助手 | 编辑器、表格或设计画布中的操作 | 行内修改、差异、局部建议 |
| 多模态操作 Agent | 图像、语音、界面状态 | 识别结果、操作轨迹、确认点 |

定时脚本只有固定规则和动作时，可以只叫自动化；当系统根据目标和反馈动态选择工具或步骤，才更符合这里的 Agent 模型。后台 Agent 还需要任务取消、通知去重、持久化和用户离线时的权限策略。交互细节见 [人机协同与主动式交互](/md/Agent/人机协同与主动式交互.md)。

## 常见误区

### ❌ 写一份严格 Prompt 就保证按顺序执行

✅ Prompt 提供指导，运行时状态机和阶段验收才约束合法转移。为什么：模型输出是候选动作，不能同时作为规则执行器和最终裁判。

### ❌ 工具全部成功就表示任务成功

✅ 还要检查最终产物是否满足用户目标。为什么：检索成功可能找错资料，写文件成功也可能写入不完整内容。

### ❌ Harness 就是某个厂商专属框架

✅ Harness 可用于描述围绕 Agent 的运行、控制和反馈系统；具体产品各有实现。为什么：概念层的工程职责不等于某个产品内部架构。

## 高频追问

### Agent 会不会无限循环？

会，如果没有最大步数、超时、重复检测和终止策略。产品上要展示“已达步数上限”，并允许用户接管。

### Workflow 和 Agent 怎么选？

步骤固定、对正确性要求极高 → 确定性工作流；步骤依赖模型判断、工具结果多变 → Agent。很多系统是混合：关键路径工作流，边缘探索交给 Agent。

### Skill 和 MCP Tool 有什么区别？

Skill 提供可复用任务方法，MCP Tool 提供可发现和调用的外部能力。按需加载、组合和 A2A 的完整对比见 [Skills、MCP 与 A2A 的区别](/md/Agent/Skills与MCP及A2A的区别.md)。

### Agent 执行到一半进程重启怎么办？

从持久化状态和产物引用恢复，先核对已发出动作的真实结果；对外部写入使用幂等键，避免重复执行。

### 怎样证明 Harness 有效果？

用同一任务集比较成功率、违规动作、耗时和成本，再注入超时、重复回调、证据不足等故障测试恢复。
