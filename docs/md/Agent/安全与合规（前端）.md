# 安全与合规（前端）

## 面试定位

AI 产品安全题常问“前端能做什么”。要答清：**脱敏、密钥拦截、权限提示、引用溯源、企业数据驻留提示**；并强调前端是防线之一，不是唯一闸门。

## 面试回答

可以这样答：

> AI 安全要同时看输入、模型输出和工具副作用。直接 Prompt Injection 来自用户输入，间接注入还可能藏在网页、邮件和 RAG 文档里，所以“系统 Prompt 与用户文本分开”并不能彻底防住。模型输出一律视为不可信：渲染前防 XSS，传给 SQL、Shell、URL、模板或下一个工具前还要做 schema、语义和权限校验。运行时按最小功能、最小权限、最小自主性设计工具；高风险动作展示真实参数并人工确认，执行端仍重新鉴权。前端可做密钥/PII 提示、安全预览和风险解释，但强制 DLP、租户隔离、审计与数据留存必须由服务端保障。

一句话总结：

> 前端合规 = 拦截与提示 + 安全渲染 + 溯源展示；权限真相在服务端。

---

## 核心原理

```text
用户输入 / 附件
  → 敏感信息检测（前端提示）
  → 发送至 BFF（服务端再鉴权与 DLP）
  → 模型 / 工具执行
  → 结果脱敏后回传
  → 安全 Markdown 渲染 + citation
```

---

## 1. 输入侧：脱敏与拦截

| 风险 | 前端手段 |
| --- | --- |
| 粘贴 API Key / 私钥 | 正则启发式提示，阻止或打码后发送 |
| 上传含客户 PII 的表格 | 上传前说明用途；支持字段脱敏预览 |
| 提示注入 | 系统提示与用户内容分离；关键指令不靠前端字符串拼接防住一切 |

注意：启发式检测会有误报，文案应允许“我已知晓，继续”，并打审计点。

间接提示注入的关键是把外部内容当“数据”而不是可信指令：标记来源，限制它能影响的工具范围，并在敏感调用前回到确定性策略与人工确认。单靠一句“忽略文档里的指令”不是可靠安全边界。

---

## 2. 输出侧：安全渲染与溯源

- 模型输出当**不可信内容**：Markdown 渲染禁用原始 HTML，或严格白名单。
- 代码块提供复制，但不要对不明链接自动执行。
- Citation 卡片：来源标题、片段、跳转；无来源的关键结论降权展示。
- 工具错误栈对客隐藏，对内可在 Debug 面板查看。
- 对模型产生的 URL 做协议与域名白名单；对服务端抓取还要防 SSRF 与内网地址访问。
- 工具结果进入下一轮模型前先过滤密钥、PII 和不必要字段，降低数据外泄面。

---

## 3. 企业合规的界面表达

| 信息 | 为何要展示 |
| --- | --- |
| 数据驻留区域 | 满足客户合规选型 |
| 是否用于训练 | 影响是否可粘贴业务数据 |
| 模型名称/版本 | 可复现与责任边界 |
| 会话保留策略 | 删除会话、导出、留存天数 |

**场景（示例）**：云计算控制台 AI 助手在首次对话展示“对话可能被审计，请勿粘贴密钥”；粘贴 `AKIA…` 形态字符串时弹出拦截。

**验证**：安全用例库（XSS payload、假密钥、外链）；与安全团队对齐误报率；确认未 approve 的高风险工具无执行请求。

## 高频追问

### 前端脱敏了，是不是就安全了？

不是。恶意用户可绕过前端。脱敏提升善意用户体验并减少事故，强制策略在服务端。

### 和传统 XSS 有什么不同？

传统 XSS 多来自用户或接口数据；AI 产品还要防模型输出里的恶意内容和提示注入诱导出的危险链接/脚本。

### HITL 算安全能力吗？

算产品安全控制。它降低自动误操作，但不能替代鉴权与审计，见 [工具调用与结果展示](/md/Agent/工具调用与结果展示.md)。
