# Cursor / Copilot 与 AI Coding

## 面试定位

岗位要求“关注 AI Coding 趋势，熟练运用 Cursor/Copilot”。面试官想区分：**你会用补全**，还是能讲清工具差异、上下文质量、以及如何纳入工程闭环。流程细节与风险控制见《平时工作怎么使用 AI》，本文偏工具能力与选型直觉。

## 面试回答

可以这样答：

> Copilot 类工具强在行内补全和常见样板；Cursor 类 Agent 更强在多文件编辑、仓库级上下文、终端与工具协同。我会按任务选工具：改小函数用补全；跨文件重构、补测试、排查报错用 Agent。提效关键不是模型本身，而是上下文质量——相关文件、接口约定、验收标准、禁止事项要给够——以及输出必须经过 lint、类型检查、单测、Review。我不会把含密钥和客户数据的内容丢进云端模型；对不确定的 API 会对照官方文档。衡量价值看交付周期、返工率和线上缺陷，而不是“写了多少行 AI 代码”。

一句话总结：

> AI Coding = 选对工具形态 + 喂对上下文 + 工程验证闭环。

---

## 核心原理

```text
明确任务与约束
  → 选择补全 / Chat / Agent
  → 提供仓库上下文与验收标准
  → 生成候选改动
  → 本地验证（lint / test / 手动）
  → Review 合入
  → 沉淀可复用 Skill / 规则
```

---

## 1. 工具形态对比

| 维度 | Copilot 类补全 | Cursor 类 Agent |
| --- | --- | --- |
| 主场景 | 行内续写、样板 | 多文件任务、重构、排障 |
| 上下文 | 当前文件/邻近为主 | 可检索仓库、规则、终端 |
| 交互 | 隐式接受/拒绝 | 显式对话与 diff 审阅 |
| 风险 | 局部错误 | 大范围误改，需更严 Review |

具体产品能力随版本变化，以官方文档为准；面试讲**形态差异**比背功能列表更重要。

---

## 2. 怎样用才算 AI Native

合格用法：

- 先写清目标、边界、非目标，再让 Agent 动手
- 要求输出短 diff、可验证步骤
- 用项目规则（coding style、目录约定）约束生成
- 把重复流程沉淀为 Skill/命令，而不是每次口头描述

不合格用法：

- 无验收标准地“帮我做一个系统”
- 不看 diff 直接全盘接受
- 用生产密钥和真实客户数据当例子

与 [平时工作怎么使用 AI](/md/面试准备/综合/平时工作怎么使用AI.md) 的分工：本文讲工具能力；那篇讲需求分析到上线的闭环与合规。

## 3. 团队效能沉淀

| 沉淀物 | 价值 |
| --- | --- |
| 项目规则 / AGENTS 说明 | 统一生成风格与禁区 |
| 常用 Skill | Review、补测试、改 changelog |
| 评测集 | 典型任务看 Agent 成功率 |
| Review 清单 | 防幻觉 API、防安全漏洞 |

**场景（示例）**：前端团队用 Agent 生成组件测试初稿，CI 强制覆盖率与类型检查；核心业务逻辑仍人工 Review。

**验证**：统计同类需求平均耗时、AI 相关回滚次数、新人上手时间。

## 高频追问

### Cursor 和 Copilot 哪个更好？

没有绝对更好。补全密度高的编码用 Copilot 类很爽；跨文件任务、需要跑命令和改多处时 Agent 更合适。很多工程师两者组合使用。

### AI Coding 会取代前端吗？

会取代大量样板劳动，但难取代业务理解、架构取舍、体验细节与质量负责。岗位更看重“用 AI 放大产能”的人。

### 如何避免幻觉 API？

对照官方文档与本仓库已有用法；让类型检查与单测尽早失败；不确定的依赖不擅自升级。
