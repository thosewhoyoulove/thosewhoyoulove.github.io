# 原型链与继承

## 面试回答

> JavaScript 的对象不会把父级成员抄到自己身上。读 `obj.foo` 时先看对象自己有没有这个属性，没有就沿着内部的 `[[Prototype]]` 继续找，直到 `null`。`Object.getPrototypeOf` 读的就是这条链，`__proto__` 是历史写法。
>
> 函数当构造器时，自己有一个 `prototype` 对象。`new` 会先建一个空对象，把它的原型指到这个 `prototype`，再用这个对象当 `this` 执行构造函数。构造函数如果返回对象，就用返回值，否则用刚建的对象。实例因此共享 `prototype` 上的方法，不用每个实例各放一份函数。`instanceof` 查的是右边的 `prototype` 在不在左边的原型链上，不是比较构造函数的名字。
>
> `class` 仍然走这套查找。`extends` 负责把子类原型接到父类原型上。方法是改在原来的原型对象上，旧实例也能看到；如果整份换掉 `Foo.prototype`，旧实例还指着旧对象。业务组件更常用组合，原型继承留给稳定的「是一个」关系。

**一句话总结：**

> 属性先找自身，再沿 `[[Prototype]]` 向上 → `new` 把实例接到构造函数的 `prototype` → 改原型对象和换掉原型对象不是一回事。

## 核心原理

`p.say()` 为什么能跑，而 `p` 自己身上又没有 `say`？调用时找到的不是一个复制过来的函数，而是实例沿原型链借到的方法。

### 1. 读属性时怎么走

访问 `obj.key`，引擎先看对象自己的属性。找到就用。找不到就取 `Object.getPrototypeOf(obj)`，在那个对象上再找一遍，直到原型是 `null`。整条路就是原型链，走到头还没有，结果是 `undefined`。

```text
实例 obj
  [[Prototype]] → Foo.prototype
                    [[Prototype]] → Object.prototype
                                      [[Prototype]] → null
```

`prototype` 和 `[[Prototype]]` 不是同一个槽。`prototype` 是函数自己的属性，准备给将来的实例当原型。`[[Prototype]]` 是每个对象都有的内部链接，`__proto__` 只是访问它的旧接口。`new` 做的事，就是把新对象的 `[[Prototype]]` 指到构造函数的 `prototype`。

方法放在 `prototype` 上，所有实例共用同一份函数。某个实例要有自己的行为，就在自己身上放同名属性，查找会先命中自身，不再继续往上。

### 2. `new` 把链接上

```javascript
function Person(name) {
    this.name = name;
}
Person.prototype.say = function () {
    return this.name;
};

const p = new Person("Ada");
```

`new Person("Ada")` 做四件事。先创建一个空对象。再把这个对象的 `[[Prototype]]` 设为 `Person.prototype`，所以它能找到 `say`。然后用这个对象当 `this` 调用 `Person`，`this.name = "Ada"` 写成实例自己的属性。构造函数没有返回对象，`new` 的结果就是这个对象。

`p.say()` 时，`p` 自己没有 `say`，沿着链在 `Person.prototype` 上找到。函数里的 `this` 仍是调用时的 `p`，所以读到的是 `"Ada"`。`this` 怎么绑定，见 [This 的理解](/md/基础/JavaScript/This的理解.md)。

如果构造函数 `return` 了一个对象，`new` 会丢掉刚建的那个对象，改用返回值。返回数字、字符串这类原始值则会被忽略，结果仍是新对象。

### 3. 改方法和换原型

`Person.prototype.say = function () { ... }` 改的是原型对象上的属性。已经创建的实例链还指着这个对象，下次调用就会走到新函数。

`Person.prototype = { say() {} }` 是另一回事。它让 `Person` 的 `prototype` 属性指向一个新对象，旧实例的 `[[Prototype]]` 仍是原来那个。旧实例继续用旧方法，`old instanceof Person` 也会变成 `false`，因为右边现在的 `prototype` 已经不在旧实例的链上。

`instanceof` 和 `isPrototypeOf` 查的都是这条链，不是构造函数名：

```javascript
p instanceof Person; // Person.prototype 是否在 p 的链上
Person.prototype.isPrototypeOf(p);
```

函数自己也是对象，所以它有 `[[Prototype]]`，普通函数一般指向 `Function.prototype`。它同时又有 `prototype`，那是给 `new` 出来的实例用的。两个链接方向不同，一个说明函数从哪来，一个说明实例往哪找方法。

### 4. 继承接的是同一条链

`class Dog extends Animal` 没有另做一套对象模型。它把 `Dog.prototype` 的原型接到 `Animal.prototype`，实例上没有的方法就继续往父类原型找。旧写法是 `Child.prototype = Object.create(Parent.prototype)`，再把 `constructor` 指回 `Child`。`class` 多出来的约束，例如必须 `new`、`extends` 同时接静态链，写在 [面向对象与原型](/md/基础/JavaScript/面向对象与原型.md)。

组件复用通常不靠这条链一层层继承下去。共享的工具函数直接导出，组件的状态和生命周期用框架自己的机制。原型题要能把查找和 `new` 讲清楚，不必把业务组件设计成深继承树。

## 常见误区

### ❌ `__proto__` 和 `prototype` 是同一个东西

### ✅ 更准确的说法

`prototype` 挂在函数上，给实例当原型。`[[Prototype]]` 是对象上的链接，`__proto__` 只是读取它的旧方式。

### 为什么？

分不清这两个槽，就解释不了 `new` 为什么能让实例找到方法，也解释不了 `instanceof` 在比较什么。

---

### ❌ `class` 是一套和原型无关的继承

### ✅ 更准确的说法

`class` 仍然建立原型链。它额外规定必须用 `new`，类方法默认不可枚举，`extends` 会把实例链和静态链一起接上。

### 为什么？

只说「语法糖」会漏掉这些差异；追问 `extends` 之后链长什么样时，还是要画回 `prototype`。语义上的差别见 [面向对象与原型](/md/基础/JavaScript/面向对象与原型.md)。

---

### ❌ 改了 `Foo.prototype` 上的方法，只有新实例生效

### ✅ 更准确的说法

改的是同一个原型对象上的属性时，已有实例下次查找就能看到。只有整份替换 `Foo.prototype = {}`，旧实例才继续指向旧对象。

### 为什么？

实例保存的是当时那个原型对象的链接，不是构造函数名字。链接没断，对象上的新属性就能被找到。

## 高频追问

### 原型链是什么？

对象自己没有某个属性时，沿着 `[[Prototype]]` 向上找，直到 `null` 的那条路径。

### `new` 做了什么？

创建对象，把原型连到构造函数的 `prototype`，用这个对象当 `this` 执行构造函数；构造函数返回对象时用返回值，否则用新对象。

### `instanceof` 看什么？

右边函数的 `prototype` 是否出现在左边对象的原型链上。换掉 `prototype` 之后，旧实例可能不再成立。

### 函数为什么既有 `__proto__` 又有 `prototype`？

函数是对象，所以有自己的 `[[Prototype]]`。它又能当构造器，所以另有一个 `prototype` 交给实例。

### 和闭包有什么不同？

闭包保留的是定义时的变量绑定。原型链解决的是对象之间共享和查找属性。一个实例方法可以同时用到两者：方法放在原型上共享，方法里若引用了外层变量，那是闭包。
