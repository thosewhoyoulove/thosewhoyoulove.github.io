# 原型链与继承

## 面试回答

> JavaScript 里对象没有传统类那种「抄一份成员」的继承，而是通过原型链做属性查找：访问 `obj.foo` 时，先找对象自身，没有就沿 `obj.[[Prototype]]`（通常是 `__proto__` / `Object.getPrototypeOf`）往上找，直到 `null`。函数作为构造器时，会有 `prototype` 对象；`new` 出来的实例的原型默认指向该 `prototype`，于是实例共享方法，避免每个实例各挂一份函数。
>
> `new` 大致会：建空对象 → 把原型连到构造函数 `prototype` → 用这个对象当 `this` 执行构造函数 → 若构造函数返回对象则用返回值，否则用这个新对象。`instanceof` 查的是右边 `prototype` 是否出现在左边的原型链上，不是看构造函数名字字符串。
>
> ES6 `class` 主要是语法糖，底层仍是原型；`extends` 会接好原型链和 `super`。社招里常追问：自己写的方法放实例上还是 `prototype` 上、改 `prototype` 对旧实例的影响、以及和 React/Vue 组件「不要用原型硬继承业务组件」的边界——框架里更常用组合而不是深继承。

**一句话总结：**

> 属性查找走原型链 → 构造函数.prototype 挂共享方法 → new 连原型并绑定 this → instanceof 查链 → class 是糖。

## 核心原理

### 1. 为什么需要原型

若每个实例都复制一份方法函数，内存浪费且难以统一修改行为。原型让实例共享方法，同时允许实例自有属性覆盖。

### 2. 整体链路（属性读取）

```text
读 obj.key
  → obj 自身有？ → 用自身
  → 否则 Object.getPrototypeOf(obj) 继续找
  → 直到 null → undefined
```

```text
函数 Foo
Foo.prototype = { constructor: Foo, ...methods }

new Foo()
  → 实例 [[Prototype]] === Foo.prototype
```

### 3. 关键关系图

```text
实例 obj
  [[Prototype]] → Foo.prototype
                    [[Prototype]] → Object.prototype
                                      [[Prototype]] → null
```

| 概念 | 白话 | 注意 |
| --- | --- | --- |
| `obj.__proto__` | 指向原型，历史用法 | 推荐 `Object.getPrototypeOf` |
| `Foo.prototype` | 构造器的「原型对象」 | 给实例当 [[Prototype]] |
| `Foo.prototype.constructor` | 默认指回 Foo | 重写 prototype 时可能丢 |

### 4. `new` 做了什么（Trace）

```js
function Person(name) {
  this.name = name;
}
Person.prototype.say = function () {
  return this.name;
};

const p = new Person("Ada");
```

| 步骤 | 结果 |
| --- | --- |
| 1. 创建 `{}` | 空对象 |
| 2. `[[Prototype]] = Person.prototype` | 能找到 `say` |
| 3. `Person.call(obj, "Ada")` | `obj.name = "Ada"` |
| 4. 构造函数无对象返回值 | 得到 `p` |
| `p.say()` | 自身无 `say` → 原型上找到，`this` 为 `p` |

### 5. `instanceof` 与 `isPrototypeOf`

```js
p instanceof Person; // Person.prototype 是否在 p 的链上
Person.prototype.isPrototypeOf(p);
```

换掉 `Person.prototype` 指向新对象后，**旧实例**的链仍指向旧原型对象，`instanceof` 可能对旧实例为 false——这是常见追问。

### 6. 继承怎么做（工程模型）

现代优先：

```js
class Animal {
  move() {}
}
class Dog extends Animal {
  bark() {}
}
```

更准确地说：`class` 仍建立原型链；`extends` 会设置 `Dog.prototype` → `Animal.prototype`，并处理 `super`。

旧写法（了解即可）：`Child.prototype = Object.create(Parent.prototype)` 再修 `constructor`。

### 7. 和框架的边界

Vue / React 组件复用更靠 **组合**（hooks、composables、高阶组件、插槽），而不是业务 class 深继承。原型题考的是语言基础，答题结尾可落到：「共享工具方法可以挂模块导出；组件状态与生命周期用框架机制，不靠原型继承组件。」

### 8. 设计取舍

| 做法 | 优点 | 代价 |
| --- | --- | --- |
| 方法放 prototype | 共享、省内存 | 理解链成本 |
| 方法放实例（构造里） | 可私有封闭 | 每实例一份 |
| class | 可读、可 extends | 仍要懂原型才能答追问 |

## 常见误区

### ❌ `__proto__` 和 `prototype` 是同一个东西

### ✅ 更准确的说法

`prototype` 是函数上的属性；`[[Prototype]]`/`__proto__` 是对象的原型指针。`new` 把两者接起来。

### 为什么？

混为一谈后无法解释 `instanceof` 和继承。

---

### ❌ class 是全新的继承体系，和原型无关

### ✅ 更准确的说法

class 是原型的语法糖（还有不能当函数调用等约束）。

### 为什么？

面试官会让你画出 `extends` 后的链。

---

### ❌ 改了 Foo.prototype.method，只有新实例生效

### ✅ 更准确的说法

改的是同一原型对象上的属性时，已有实例也能通过链访到新方法；若整体替换 `Foo.prototype = {}`，旧实例仍指向旧对象。

### 为什么？

要区分「改原型对象内容」和「换原型对象引用」。

## 高频追问

### 原型链是什么？

对象属性查找失败时，沿 [[Prototype]] 向上找的链条。

### new 做了什么？

创建对象、连接原型、绑定 this 执行构造、处理返回值。

### instanceof 判断依据是什么？

右边 `prototype` 是否在左边原型链上。

### 如何实现继承？

现代用 `class extends`；本质仍是接原型链。也可 `Object.create`。

### 函数为什么既有 `__proto__` 又有 `prototype`？

函数是对象，所以有 [[Prototype]]（通常是 Function.prototype）；同时函数可作为构造器，自带 `prototype` 给实例用。

### 和闭包有什么不同？

闭包关乎词法作用域与变量持久；原型关乎对象属性共享与查找。常一起考但不互相替代。
