# 面向对象与原型

## 面试回答

可以这样答：

> JavaScript 是基于原型的多范式语言，可以写面向对象代码，但继承方式是原型委托，不是把父类成员复制到子类。ES6 的 `class` 大部分是这套机制的语法糖，另外强制 `new`、类体严格模式、方法默认不可枚举。封装、继承、多态都有：封装靠闭包或 `#` 私有字段藏状态，继承靠原型链，多态靠同一调用约定、不同对象各自实现。
>
> `new` 会创建对象、把内部原型指到构造函数的 `prototype`、用这个对象当 `this` 执行构造函数；构造函数如果返回对象，就用返回值，否则用新对象。属性读取先看自身，再沿 `[[Prototype]]` 往上，直到 `null`。赋值数据属性时通常在当前对象上新建自身属性，不会改原型上的值。
>
> TypeScript 类的 `extends` 是运行时继承，`implements` 只在编译期检查形状，编译后消失。`private` / `protected` 也主要是编译期检查；真正的运行时私有要用 `#` 字段。业务里我更倾向组合：把会变化的格式化、校验、渲染策略注入进去，只在稳定的「是一个」关系上用继承，比如错误类型、框架基类。

一句话总结：

> JS 的面向对象 = 对象 + 原型委托；`class` 是语法层；TS 的 `implements` 和访问修饰符是编译期约束。

---

## 核心原理

同一组业务对象既要共享行为，又要保留各自的状态。JavaScript 用原型委托共享方法，用实例字段保存状态；TypeScript 则在编译期检查它们是否满足约定。下面先区分这两层，再讨论复用应该用继承还是组合。

### 1. JavaScript 怎样支持面向对象

是。它支持用对象封装状态和行为，也支持委托式继承和多态，所以是面向对象语言。它同时是多范式语言，函数式、命令式、事件驱动都能写。

和 Java / C# 的差别在继承机制：

| | 基于类的语言 | JavaScript |
| --- | --- | --- |
| 复用方式 | 类继承，子类得到父类结构 | 原型委托，运行时沿 `[[Prototype]]` 查找 |
| 类的地位 | 类是创建对象的模板，通常编译期存在 | 函数或 `class` 都是运行时的值；`class` 仍基于原型 |
| 类型约束 | 接口、访问修饰符多数进入类型系统甚至运行时 | 语言本身靠鸭子类型；`interface`、`private` 来自 TypeScript，编译后擦除 |

不要答成「JS 不是面向对象，因为它早期没有 class」。`class` 出现之前，构造函数加原型已经是面向对象。

---

### 2. 封装、继承与多态怎样落到业务

面试常说的三个是封装、继承、多态。抽象有时单独算第四个：抽出稳定模型，调用方不依赖具体实现。

| 特性 | 在 JS 里是什么 | 示例 |
| --- | --- | --- |
| 封装 | 只暴露操作，藏住状态。闭包、`#` 字段是真隐藏；下划线前缀只是约定 | 请求客户端藏 `baseURL`、token 刷新 |
| 继承 | 子对象自己没有的属性，委托给原型继续找 | `class UploadClient extends RequestClient` |
| 多态 | 调用方只依赖同一方法名，具体对象行为不同 | 折线图和柱状图都有 `render(data)` |

项目例子可以收成一个图表模块（示例）：`Chart` 封装数据校验和容器尺寸；`LineChart`、`BarChart` 继承公共的 `resize`；页面只调用 `renderer.render(data)`，切换图表类型不用改调用方。这就是多态。

边界：UI 组件树里深继承很快会僵。三大特性都要有，不代表默认用继承实现复用。组合的取舍见下文。

---

### 3. class 增加了什么语义

两者创建实例的底层都是原型。`class` 不是另一套对象模型，但语义并不和 `function` 完全等价。

| | 构造函数 | `class` |
| --- | --- | --- |
| 调用 | 普通函数可以不带 `new`；独立调用时 `this` 取决于严格模式 | 必须 `new`，否则 `TypeError` |
| 严格模式 | 看函数定义所在的严格模式上下文 | 类体始终是严格模式 |
| 提升 | 函数声明会提升 | 类声明存在暂时性死区，不会像函数声明那样提前可用 |
| 原型方法 | 赋到 `prototype` 上的方法默认可枚举 | 类方法默认不可枚举 |
| 方法能否 `new` | 普通函数方法可以再被 `new` | 类方法没有 `[[Construct]]`，不能当构造函数 |
| 继承 | 需要显式连接实例原型链与构造函数的静态原型链 | `extends` / `super` 同时接实例链和静态链 |
| 私有状态 | 闭包 | 支持 `#` 字段、静态块 |

```js
function Person(name) {
    this.name = name;
}
Person.prototype.say = function () {
    return this.name;
};

class User {
    constructor(name) {
        this.name = name;
    }
    say() {
        return this.name;
    }
}
```

子类构造函数里，使用 `this` 之前必须先 `super()`。实例对象在 `super()` 进入父类构造时完成初始化。

什么时候用哪个：新代码用 `class`，继承和严格模式更难写错。读老代码、解释原型题时，要能把 `class` 还原成构造函数加 `prototype`。

### 原型机制在哪里展开

对象读取属性时先找自身，再沿原型链查找；普通构造函数通过 `new` 创建实例并连接原型。这里保留这条主线，具体的 `new` 返回值、`constructor`、原型替换与属性查找示例见 [原型链与继承](/md/基础/JavaScript/原型链与继承.md)。

`this` 的绑定规则见 [This 的理解](/md/基础/JavaScript/This的理解.md)，构造调用与参数预置的手写实现见 [call、apply 和 bind](/md/基础/JavaScript/函数的call,apply和bind方法.md)。它们解决调用机制，本篇继续讨论类型约束和复用方式。

### 4. extends 和 implements 分别改变什么

类声明中的 `extends` 在 JavaScript 和 TypeScript 里都有运行时效果。`implements` 只有 TypeScript，编译后删除。

| | `extends` | `implements` |
| --- | --- | --- |
| 作用层 | 运行时建立原型链，子类得到父类实现 | 编译期检查类的实例侧是否满足接口 |
| 数量 | 类只能 `extends` 一个父类 | 一个类可以 `implements` 多个接口 |
| 得到实现吗 | 会 | 不会。接口里没有可执行的方法体 |
| 用在哪 | 类继承类；接口也可以 `extends` 接口，那只是类型继承 | 类声明「我承诺有这些成员」 |

```ts
interface Readable {
    read(): string;
}

interface Writable {
    write(value: string): void;
}

class Store {
    save() {
        return "saved";
    }
}

class FileStore extends Store implements Readable, Writable {
    read() {
        return "file";
    }
    write(_value: string) {}
}
```

`FileStore` 运行时真的能调用 `save`，因为 `extends Store`。`read` / `write` 必须自己写，`implements` 不会帮你生成。漏写会在 `tsc` 报错，编译产物里看不到 `implements`。

接口的 `extends` 和类的 `extends` 不要混：`interface Admin extends User` 只是类型继承，没有原型链。

### 5. interface 和抽象类怎样选择

两者都能描述「子类必须实现什么」。差别是接口只活在类型系统里，抽象类编译后仍是构造函数，并且可以带已经实现的方法。

| | `interface` | `abstract class` |
| --- | --- | --- |
| 运行时 | 完全擦除 | 仍是函数 / 类，可以放具体方法、字段、构造函数 |
| 能否 `new` | 不存在运行时值 | TypeScript 禁止直接 `new`。这是编译期检查，产物里默认没有额外的运行时拦截 |
| 实现 | 不能有方法实现 | 可以有具体方法，抽象方法留给子类 |
| 组合方式 | 一个类可以实现多个接口 | 一个类只能继承一个抽象类 |
| 访问修饰符 | 成员对外可见，不能写 `private` / `protected` | 可以写 `public` / `protected` / `private` |

```ts
interface Exporter {
    export(rows: string[][]): string;
}

abstract class ReportJob {
    constructor(protected name: string) {}

    abstract run(): string;

    label() {
        return this.name;
    }
}
```

选择：只约束数据结构或调用形状，用 `interface`，方便一个类实现多个能力。需要复用一段真正的运行时代码，又要禁止直接实例化基类，用抽象类。如果基类里的具体方法很少，优先改成组合，把这段逻辑做成独立对象。

抽象类不能被 `new`，指的是 TypeScript 编译失败。绕过类型检查去跑编译后的 JavaScript，仍然可能把这个构造函数调起来。不要把它理解成 Java 那种运行时抽象类。

### 6. 访问修饰符能保护到哪一层

这三个是 TypeScript 的编译期可见性。默认是 `public`。

| | 类外部 | 子类 | 运行时 |
| --- | --- | --- | --- |
| `public` | 可以 | 可以 | 普通属性 |
| `protected` | 不可以 | 可以 | 仍是普通属性，编译后外部照样能访问 |
| `private`（关键字） | 不可以 | 不可以 | 仍是普通属性，名字还在 |
| `#field` | 不可以 | 不可以 | ECMAScript 真私有字段，类外部访问会失败 |

```ts
class Account {
    public id: string;
    protected role = "user";
    private token = "ts-private";
    #secret = "runtime-private";

    constructor(id: string) {
        this.id = id;
    }
}
```

编译后 `token` 还是 `this.token`，控制台和 `JSON.stringify` 都能看到。`#secret` 不会变成普通字符串键，类外面写 `account.#secret` 在语法上就不成立。

使用约定：

- 只是提醒调用方别依赖，用 `private` 即可，知道它挡不住运行时。
- 需要运行时封装的状态可以用 `#` 或闭包；它们不是抵御恶意脚本的安全隔离机制。
- `protected` 适合框架基类留给子类的钩子。它会鼓励继承，对外 SDK 要慎用，否则子类会绑死父类内部结构。

同一类的方法里可以访问另一个实例的 `private` 成员。子类不行。这是 TypeScript `private` 的可见性规则，不是「每个对象一份完全隔离的运行时权限」。

### 7. 为什么把变化交给组合

继承是「是一个」，子类会拿到父类的全部实现，也包括以后父类加上的行为。层级一深，改父类就会波及所有子类，这就是脆弱基类。

组合是「有一个」。对象拿着协作者，只调用对方的接口。协作者可以替换，测试时可以换成假的实现。

```ts
interface Formatter {
    format(rows: string[][]): string;
}

// 教学示例：仅演示组合，未实现 CSV 的引号与换行转义。
class CsvFormatter implements Formatter {
    format(rows: string[][]) {
        return rows.map((row) => row.join(",")).join("\n");
    }
}

class ExportService {
    constructor(private formatter: Formatter) {}

    export(rows: string[][]) {
        return this.formatter.format(rows);
    }
}
```

如果做成 `CsvExport extends BaseExport`、`ExcelExport extends BaseExport`，公共基类里一旦混进文件名、权限、下载进度，每种导出都会被迫继承这些状态。新增一种格式还要再开一个子类。组合只换 `formatter`。

仍然适合继承的情况：

- 关系稳定，而且子类确实是父类的一种，比如自定义 `Error`。
- 框架规定了扩展点，比如 React 的 `ErrorBoundary` 必须继承 `React.Component`。
- 需要沿原型共享少量稳定行为，并且子类很少。

前端 UI 更常见的组合是：组件 `children`、Vue 插槽、hooks / composables，而不是 `BasePage`、`ListPage`、`AdminListPage` 这种页面继承树。React 官方文档也把组合作为复用 UI 的默认方式。

### 8. 用设计模式解释变化点

不要背 23 种。挑 4～6 个你能讲清「变化点在哪、怎么验证」的即可。下面按本知识库里的项目场景来组织，面试时换成自己真正写过的模块。

| 模式 | 解决什么 | 可讲的场景 | 边界 |
| --- | --- | --- | --- |
| 状态机 | 禁止非法状态组合 | 云呼通话：空闲、拨号、通话、挂断，不能同时「通话中」又「未连接」 | 状态少时用几个布尔量就够，不必上完整库 |
| 单例 | 同一页面运行环境复用一个实例 | 页面内复用一个通话客户端，避免重复初始化 | 单例隐藏依赖，测试要能替换实例 |
| 策略 | 同一流程、不同算法 | 高级筛选的表格视图和卡片视图，共用查询条件，渲染策略分开 | 策略爆炸时用注册表，不要写成长 `if` |
| 适配器 | 外部结构和内部模型不一致 | 筛选选项、CRM 字段映射成前端视图模型 | 适配层只做结构转换，不写业务判断 |
| 发布订阅 | 生产者和消费者解耦 | Vue 2 升级时，把 `Vue.prototype` 事件总线换成 `mitt` | 必须成对解绑，否则页面离开后仍收到旧回调 |
| 装饰器 / 中间件 | 给一次调用加横切能力 | 请求拦截器统一补 token、打日志、处理 401 | 拦截器顺序就是行为，顺序错了很难查 |

口述可以收成这样：

> 筛选列表我用策略把表格和卡片拆开，查询条件是同一份，展示可以换。导出用组合注入 `formatter`，而不是为每种文件格式建子类。通话类功能用状态机限制合法跳转，并在页面内复用一个客户端，跨标签互斥另外设计协调机制。事件通知用发布订阅，组件销毁时解绑。这些模式我都会配单测：策略看输出，状态机看非法跳转被拒绝，订阅看卸载后不再触发。

模式是结构名字。面试官追问时，回到「哪一段代码经常变、怎么隔离、怎么验证」。

## 常见误区

- **把 class 当成原型之外的新对象模型**：实例仍沿原型查找方法；class 另外规定了严格模式、构造调用与私有字段等语义，因此不能说它与普通函数完全等价。
- **把 implements 当成代码复用**：它只检查实例形状，不会生成方法。需要共享实现时，再选择组合或类继承。
- **把 private 当成运行时安全屏障**：TypeScript 的访问修饰符主要约束编译期。运行时封装与防御恶意脚本是不同层次的问题。
- **把页面单例当成跨标签单例**：每个标签有自己的 JavaScript 环境。跨页面共享任务可考虑 SharedWorker；连接互斥仍需明确协调与故障恢复，普通模块单例不能自动实现。

## 高频追问

### 改了原型，旧实例会变吗？

实例还没有同名自身属性时会变，因为它读的就是原型上的那个值。已经在实例上赋过值的属性不会跟着变。

### `class` 是不是 100% 语法糖？

创建实例、原型委托这条主路径可以这么理解。强制 `new`、类体严格模式、方法不可枚举、`super`、`#` 私有字段，都是构造函数不会自动具备的语义。

### 为什么 `obj.method()` 和把 method 拿出来调用，`this` 不一样？

隐式绑定看的是调用点，不是定义点。拆开之后调用点不再是 `obj.`，就回到默认绑定。要用箭头函数包一层，或者 `bind`。

### TypeScript 的 `private` 能保护 token 吗？

不能。编译后仍是对象上的普通属性。`#` 字段或闭包能避免普通属性访问和意外序列化，但不能阻止同源恶意脚本拦截输入或调用公开方法。

### 什么时候继承仍然合理？

稳定的「是一个」，而且子类数量少、父类几乎不再加行为。错误类型、框架指定的基类属于这种。页面、表单、导出格式这类会继续长的需求，用组合。
