# JavaScript 数据类型

## 面试回答

> JavaScript 有 7 种原始类型和 1 种对象类型。原始类型是 `undefined`、`null`、`boolean`、`number`、`string`、`symbol`、`bigint`，数组、函数、日期这些都是对象。赋值时，原始类型复制的是值本身，改副本不会影响原来的变量；对象复制的是引用，两个变量指向同一块数据，改属性两边一起变。
>
> 判断类型时，`typeof` 能认出大部分原始类型和函数，但 `typeof null` 是 `"object"`，数组也会得到 `"object"`。数组用 `Array.isArray`，需要区分 Date、正则这类对象时用 `Object.prototype.toString.call`。`undefined` 多是还没赋值或属性不存在，`null` 是我们故意表示「这里现在没有对象」。`Symbol` 用来做不会撞名的属性键，`BigInt` 用来表示超出安全整数范围的整数，而且不能和普通 `Number` 直接运算。

**一句话总结：**

> 原始值按值复制，对象按引用共享 → `typeof` 覆盖不了 `null` 和数组 → 嵌套对象要不要再复制，决定浅拷贝还是深拷贝。

## 核心原理

`b = a` 之后改 `b`，为什么数字没变、对象的属性却变了？差别不在变量写在哪一行，而在赋过去的是一份独立的值，还是指向同一对象的引用。

### 1. 赋值时到底复制了什么

规范把类型分成原始类型和 Object。原始值没有可被原地修改的属性：你写下 `b = 2`，是让 `b` 改指另一个值，`a` 仍然是 `1`。对象值是一块可修改的数据，变量里放的是对它的引用。`obj2 = obj1` 只是又记了一次同一个对象，所以 `obj2.count = 2` 改的就是 `obj1` 看到的那份数据。

```javascript
let a = 1;
let b = a;
b = 2;
console.log(a); // 1

const obj1 = { count: 1 };
const obj2 = obj1;
obj2.count = 2;
console.log(obj1.count); // 2
```

比较也沿这条规则。`===` 对原始值比的是类型和值，对对象比的是是不是同一个引用。两个字面量 `{}` 各创建一个对象，所以 `{} === {}` 是 `false`。

引擎实现里，字符串、`BigInt` 未必真的躺在调用栈上。面试要讲的是语言语义：原始值赋值得到独立的值，对象赋值共享同一份数据。不要把「栈和堆」说成规范保证。

### 2. `typeof` 为什么经常不够

`typeof` 对 `undefined`、`boolean`、`number`、`string`、`symbol`、`bigint` 和函数都能给出对应字符串。函数在类型上仍是对象，只是 `typeof` 单独返回 `"function"`。

它有两个会在追问里出现的结果：

```javascript
typeof null; // "object"
typeof []; // "object"
```

`null` 被报成 `"object"` 是早期实现留下来的。当时用值的低位类型标签区分类型，对象的标签是 `0`，而 `null` 用全 0 的空指针表示，标签撞在一起。后来为了不改坏已经上线的网页，这个结果被保留下来。数组本来就是对象，所以 `typeof` 分不出数组和普通对象。

`instanceof` 走的是原型链：它看右边构造函数的 `prototype` 是否出现在左边对象的链上。数组因此既 `instanceof Array`，也 `instanceof Object`。换一个 iframe 或另一个 realm，两边的 `Array` 不是同一个函数，`instanceof` 会失败。`Array.isArray` 查的是数组这个内建标记，跨窗口仍然有效，业务里判断数组优先用它。

要连 `null`、Date、正则一起认出来，用 `Object.prototype.toString.call`。它读取对象的内部标记，`null` 和 `undefined` 也会被特判成 `"[object Null]"`、`"[object Undefined]"`。对象可以自设 `Symbol.toStringTag`，所以这不是防篡改的安全检查，只是比 `typeof` 细的类型标签。

### 3. `null` 和 `undefined` 各表示什么

`undefined` 是「还没有值」：变量声明了没赋值、访问不存在的属性、函数没有 `return`，都会得到它。`null` 是写代码的人放进去的空位，表示这里本该是一个对象，但当前没有。

```javascript
let a;
console.log(a); // undefined

const user = null; // 明确表示暂无用户
```

`null == undefined` 为 `true`，`null === undefined` 为 `false`。`==` 把这一对单独当成相等，并不会把 `null` 转成 `0`，所以 `null == 0` 是 `false`。接口和 DOM 查询常用 `null` 表示没找到，JSON 里也只有 `null`，没有 `undefined`。

### 4. `Symbol` 和 `BigInt` 补上了哪两种值

`Symbol("id")` 每次调用都得到一个新的值，描述字符串只是调试用的名字，不参与相等判断。把它当属性键，就不会和别人的字符串键 `"id"` 撞在一起。`Object.keys` 和 `JSON.stringify` 都不会带上 Symbol 键。需要跨文件拿到同一个 Symbol 时用 `Symbol.for`，那是全局注册表，和直接调用 `Symbol()` 不是一回事。

`Number` 能精确表示的整数到 `Number.MAX_SAFE_INTEGER`，也就是 `2^53 - 1`。再往上，相邻整数可能变成同一个浮点值：

```javascript
Number.MAX_SAFE_INTEGER + 2 === Number.MAX_SAFE_INTEGER + 1; // true
```

这种整数用 `BigInt`。它和 `Number` 是两种类型，`1n + 1` 会抛 `TypeError`，要先变成同一种再算。`JSON.stringify` 遇到 `BigInt` 也会抛错，传给接口前要自己转成字符串。

### 5. 拷贝为什么会停在第一层

浅拷贝复制的是对象自己的那一层属性。属性值如果是数字，复制出去的是一个新值；如果是对象，复制出去的仍是原来的引用。`Object.assign` 和对象展开都是浅拷贝。

```javascript
const source = { count: 1, meta: { title: "a" } };
const copy = { ...source };
copy.count = 2;
copy.meta.title = "b";
console.log(source.count); // 1
console.log(source.meta.title); // "b"
```

深拷贝要继续走进去，给嵌套对象也做一份新的。`JSON.parse(JSON.stringify(value))` 只能覆盖能进 JSON 的数据：函数、`undefined`、Symbol 会被丢掉，Date 变成字符串，循环引用会抛错。`structuredClone` 能保留 Date、Map、Set，但遇到函数会抛 `DataCloneError`。项目里如果对象上挂着方法或回调，不要指望一个通用深拷贝把行为也复制走，通常只克隆数据，函数留在原处。

## 常见误区

### ❌ 原始类型一定存在栈上，对象一定存在堆上

### ✅ 更准确的说法

能稳定回答的是赋值语义：原始值复制值，对象复制引用。引擎可以把字符串放在堆上，再用指针传递，调用方仍然不能原地改掉另一个变量里的原始值。

### 为什么？

把存储位置说成语言规则，一追问「长字符串在哪」就接不上。

---

### ❌ `typeof` 能判断所有类型

### ✅ 更准确的说法

它适合原始类型和函数。`null` 和数组都要换判断方式。

### 为什么？

`typeof null === "object"` 是保留下来的历史结果，不是 `null` 真的属于对象类型。

---

### ❌ 浅拷贝之后两个对象就互不影响

### ✅ 更准确的说法

第一层的原始值互不影响，嵌套对象仍然共用。

### 为什么？

浅拷贝只复制属性当前持有的值；那个值如果是引用，两边继续指向同一个对象。

## 高频追问

### 为什么 `typeof null` 是 `"object"`？

早期实现用类型标签区分值，对象标签和表示 `null` 的空指针撞在了一起。为了兼容已有网页，这个结果留到了现在。

### `==` 和 `===` 差在哪？

`===` 不做类型转换，类型不同就是 `false`。`==` 会按抽象相等规则转换，例如 `0 == false`、`null == undefined`。另外 `NaN === NaN` 是 `false`，`+0 === -0` 是 `true`；要同时区分这两种情况用 `Object.is`。业务代码默认用 `===`。

### 深拷贝和数据类型是什么关系？

对象属性里存的可能又是引用。只复制第一层时，嵌套对象仍然共享；深拷贝才为每一层对象新建一份。选 `JSON` 还是 `structuredClone`，取决于数据里有没有 Date、Map、函数和循环引用。

### `Symbol` 当键和字符串键有什么不同？

每次 `Symbol()` 都是新值，不会和已有字符串键重名，普通枚举和 `JSON.stringify` 也看不到它。`Symbol.for` 才会按描述去全局注册表里取同一个值。
