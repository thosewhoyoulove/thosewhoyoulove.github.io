# Vue 模板编译流程

## 面试回答

> Vue 模板不会直接变成 DOM，而是编译成 render 函数。大致三步：parse 把模板解析成 AST；transform 处理指令与表达式，并做静态提升、patchFlag、事件缓存、Block Tree 等优化；codegen 生成可执行的 render 代码。运行时执行 render 得到 VNode，再 patch。
>
> 模板比任意 JSX/JS 更受约束，所以编译器能静态看出哪些节点永远不变、哪些 props/文本是动态的。更新时运行时就可以跳过大量静态结构，只碰动态点——这是 Vue「默认少手动 memo」的重要原因之一。面试不必背 AST 字段名，但要能说清：编译把信息喂给 runtime，Diff 才能更省。

**一句话总结：**

> template → AST → transform（提升/patchFlag/Block）→ render → VNode → patch。

---

## 核心原理

### 1. 为什么要编译

人写模板；浏览器要的是 JS。编译还可**提前分析**，把优化从运行时挪到构建/首次编译。

---

### 2. 三阶段

```text
template
  → parse：字符串 → AST
  → transform：指令、表达式、静态分析与优化标记
  → codegen：AST → render 函数代码
  → 运行时 render() → VNode → patch
```

```vue
<template>
  <div>
    <p>{{ msg }}</p>
  </div>
</template>
```

心智上会生成类似 `h('div', null, [h('p', null, ctx.msg)])` 的逻辑；真实产物会带优化参数。

---

### 3. 关键优化分别解决什么

| 优化 | 解决什么 |
| --- | --- |
| 静态提升 | 不变节点别每轮 recreate |
| patchFlag | 告诉 runtime「这个节点动的是文本还是 class/props…」 |
| Block Tree | 动态子节点收集起来，跳过中间静态骨架 |
| cacheHandlers | 事件函数引用稳定，减少子组件无谓更新 |

没有这些，每次更新都更接近「整段 children 盲比」。

---

### 4. 与渲染 / Diff 的关系

```text
编译产出的标记
  → 运行时 patch 读标记
  → 少创建、少比较、少进 patchKeyedChildren
```

详见 [Vue 渲染原理](/md/框架/Vue/Vue%20渲染原理.md)、[Vue Diff](/md/框架/Vue/Vue%20Diff算法.md)。

---

### 5. 设计取舍

约束语法换静态分析；复杂 UI 仍可用 render 函数 / JSX，但优化信息可能变少。

## 常见误区

### ❌ 模板编译就是生成 HTML 字符串

### ✅ 更准确的说法

生成的是 render 函数（再产出 VNode），不是拼好的 HTML（SSR 另有渲染路径）。

---

### ❌ patchFlag 在手写时每次都要自己标

### ✅ 更准确的说法

模板编译自动生成；手写 h/VNode 一般拿不到同等优化。

---

### ❌ 有编译优化就可以不写 key、不拆组件

### ✅ 更准确的说法

列表身份、组件边界仍重要；编译减的是静态与标记清晰的动态点成本。

---

## 高频追问

### Vue 为什么比纯运行时 JSX 更容易做编译优化？

模板结构更可静态分析；任意 JS 表达式难证明「这段永远不变」。

### patchFlag 是什么？

编译打在 VNode 上的动态类型标记，指导精准 patch。

### 静态提升解决什么？

避免每次 render 重建不变 VNode。

### Block Tree 解决什么？

把动态节点抽出收集，更新时直达，少遍历静态中间层。

### 运行时 only 的构建有什么差别？

若只用运行时、模板都预编进 JS，体积与路径不同；优化思想仍依赖编译步骤发生在何处。
