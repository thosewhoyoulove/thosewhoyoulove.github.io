# 打包优化面试专题

## 面试回答

> 打包优化我先分两条线：**构建速度**（本地/CI 等多久出包）和**线上加载**（体积、请求、缓存、执行）。Webpack 是 entry → 依赖图 → loader → chunk → assets；Vite 开发靠 ESM 按需编译 + esbuild 预构建，生产仍 Rollup。优化前先用耗时分析、bundle analyzer、Network/Lighthouse 定位，再对症：缓存与缩小编译范围提速；Tree Shaking、分包、压缩、hash 长期缓存改善加载。不会无指标堆配置。Tree Shaking 删无用导出，分包改加载时机与缓存粒度，问题不同。

**一句话总结：**

> 先测瓶颈 → 构建速度与加载性能分治 → 缓存/范围/摇树/分包/压缩按需上。

## 核心原理

### 1. 总链路

```text
入口 → 解析与转换 → 依赖图 → chunk 拆分
  → Tree Shaking / minify / hash
  → assets → CDN/浏览器缓存与执行
```

## 常见误区

### ❌ 优化 = 把所有推荐配置糊上

### ✅ 更准确的说法

先定位是编译慢还是包大还是缓存差。

---

### ❌ Vite 快所以生产也不用打包

### ✅ 更准确的说法

快在开发；生产仍要打包优化。

---

### ❌ 分包越细越好 / 有 Tree Shaking 就不用分包

### ✅ 更准确的说法

两者解决不同问题；过细分包有请求与调度成本。

## 高频追问

### 从哪下手？

构建慢看 loader 耗时与缓存；包大看分析与重复依赖；线上慢看首屏资源与瀑布图。

### 如何证明有效？

构建耗时、主包体积、LCP、缓存命中、路由懒加载耗时。

### Webpack 持久缓存注意什么？

缓存键与失效条件；改 loader/配置后要能正确 bust。
