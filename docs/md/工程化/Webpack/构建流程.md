# Webpack 构建流程

## 面试回答

> Webpack 可以概括成：从 entry 出发递归建模块依赖图，再打成可部署的 chunk/assets。启动时读配置、创建 `Compiler` 并注册 plugin；每次构建新建 `Compilation`，对入口做 resolve → loader 转换 → parser 分析 `import`/`require`，递归把依赖收进 ModuleGraph，再按入口、动态 import、`splitChunks` 等生成 ChunkGraph。优化阶段做 Tree Shaking、合并、压缩等，最后把 chunk 变成 assets，在 emit 写出磁盘。Plugin 通过 Tapable 钩子插在这些阶段上，所以它不是「黑盒一次变文件」，而是「图构建 + 生命周期可扩展」。

**一句话总结：**

> Compiler 管全局 → Compilation 单次编译 → resolve/loader/parser 建图 → chunk → 优化 → emit assets。

---

## 核心原理

### 1. 为什么是「图」而不是「拼文件」

打包器要知道：谁依赖谁、哪些该进同一 chunk、哪些能删、哪些要异步加载。没有依赖图，分包和 Tree Shaking 都没有输入。

---

### 2. 主链路

```text
读配置 / 注册 plugin
  → new Compiler
  → run → new Compilation
  → 从 entry 建模块
       resolve → loader 链 → 得到可解析源码
       parser → 发现依赖 → 递归
  → ModuleGraph / ChunkGraph
  → 优化（tree shake、splitChunks、minify…）
  → 生成 assets
  → emit 到 output
```

| 对象 | 一句话 |
| --- | --- |
| Compiler | 一次 Webpack 进程级环境与全局钩子 |
| Compilation | **这一次**编译的模块、chunk、asset |
| loader | 单文件变成 Webpack 能懂的模块 |
| plugin | 在钩子里读写编译结果 |
| chunk | 最终输出单元的模块集合 |

---

### 3. 最小 Trace

```text
main.js
  import App from './App'
  import './style.css'
```

| 步骤 | 发生什么 |
| --- | --- |
| entry | 创建 main 模块 |
| App | JS loader（如 babel）→ 再挖依赖 |
| style.css | css-loader 等 → CSS 依赖进图 |
| chunk | 按策略进 main / 异步 / vendor |
| emit | js/css 等资源落盘 |

---

### 4. 和 Vite 开发态对比（一句）

Webpack 传统强项是统一图与强定制；开发冷启动常更重。Vite 开发按需 ESM，生产再用打包器。流程题仍常考 Webpack，因为概念完整。

---

### 5. 设计取舍

一切进图 → 优化空间大、插件强；代价是配置复杂、大项目编译成本高（靠缓存、缩小范围缓解）。

## 常见误区

### ❌ Webpack 就是把文件拼成一个 bundle

### ✅ 更准确的说法

先建依赖图再生成一个或多个 chunk，还有异步与优化阶段。

---

### ❌ Compiler 和 Compilation 是同一个东西

### ✅ 更准确的说法

Compiler 长生命周期；Compilation 每次构建一份。

---

### ❌ loader 和 plugin 阶段随便混用说法

### ✅ 更准确的说法

loader 在模块构建；plugin 贯穿生命周期。见 [Loader 与 Plugin](/md/工程化/Webpack/Loader与Plugin.md)。

---

## 高频追问

### Webpack 构建主流程？

初始化 Compiler → Compilation → 建 ModuleGraph → Chunk → 优化 → emit。

### Module 和 Chunk 区别？

Module 是图上的节点；Chunk 是输出分组，一个 chunk 含多个 module。

### 动态 `import()` 在流程里意味着什么？

通常产生异步 chunk 分裂点，影响 ChunkGraph。

### 插件何时介入？

`apply(compiler)` 挂 Tapable 钩子，在 compile/emit/done 等阶段执行。
