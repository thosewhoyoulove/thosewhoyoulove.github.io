# Vite 开发环境与生产环境打包差异

## 面试回答

> Vite 故意做成两套策略，因为目标和约束不同。开发要冷启动快、改完立刻看见：用原生 ESM 按需编译，依赖用 esbuild 预构建，不做全量打包。生产要下载少、执行省、缓存稳：用 Rollup 做完整打包，配合 Tree Shaking、代码分割、压缩、CSS 提取等。所以开发不能拿 Rollup 全量打——启动和 HMR 会随项目变慢；生产也不能直接裸奔源码 ESM——请求过多、缺少深度优化。面试抓一句：开发优化反馈延迟，生产优化加载性能。

**一句话总结：**

> Dev：ESM 按需+预构建；Prod：Rollup 打包+摇树压缩分包；目标不同所以工具不同。

---

## 核心原理

### 1. 两套逻辑

| | 开发 | 生产 |
| --- | --- | --- |
| 模块加载 | 浏览器原生 ESM | 打包后的少量 chunk |
| 转换 | 按需，常 esbuild | Rollup 图 + 优化管道 |
| 依赖 | 预构建缓存 | 打进产物 / 拆 vendor |

```text
开发：请求 → 转换单模块 → 返回 ESM
生产：源码 → Rollup → shake/split/minify → 静态资源
```

---

### 2. 为什么开发不能全量打包

全量打包：解析全图 → 编译 → 生成 bundle。项目越大越慢；改一处易牵动大切片。按需编译把成本摊到「当前用到的模块」。

---

### 3. 为什么生产不能裸 ESM

| 问题 | 说明 |
| --- | --- |
| 请求数 | 源文件 + 依赖文件可能成百上千 |
| 优化缺失 | 深层 shake、压缩协同、CSS 提取难 |
| 缓存 | 碎片文件导致缓存策略难做 |

HTTP/2 缓解传输并发，不消除解析与执行成本。

---

### 4. 同构风险（面试加分）

开发与生产路径不同，可能出现「本地正常、打出来才挂」。要用生产构建预览、CI 构建产物冒烟来兜底。

---

## 常见误区

### ❌ 生产也走和开发完全同一套 ESM 服务

### ✅ 更准确的说法

生产出静态包给 CDN/Nginx；不是把 Vite dev server 开到公网当生产。

---

### ❌ 有 HTTP/2 就可以生产不打包

### ✅ 更准确的说法

仍建议打包；请求与执行开销还在。

---

## 高频追问

### 开发用 esbuild、生产用 Rollup 会不会行为不一致？

可能。重要逻辑用生产构建验证；关注各工具对语法/目标浏览器的差异。

### 预构建算开发还是生产？

开发。生产 CJS 由 Rollup 插件链处理。

### 如何本地验证生产包？

`vite build` + `vite preview`（或等价静态服务器）。
