# 为什么 Vite 快？

## 面试回答

> Vite 快，主要快在**开发阶段**，而且要分清两套目标。传统 Webpack 开发服务器启动时，往往要从入口递归建依赖图、转译、打包，项目越大冷启动越慢；改一个文件也可能牵动较大范围的重建。Vite 开发态利用浏览器原生 ESM：先很快拉起 dev server，浏览器请求到哪个源码模块，才按需用 esbuild 等做转换，不做「先打一个大包再伺候页面」。
>
> 第三方依赖另走**依赖预构建**：用 esbuild 把 CJS/UMD 转成 ESM，并把内部文件很多的包收成更少模块，避免 `lodash-es` 那种一次几百个请求。HMR 时浏览器主要重新拉取变更模块和热更新边界，不必整包重打。生产环境 Vite 默认仍用 **Rollup 打包**：线上要控请求数、做 Tree Shaking、分割和压缩，原生 ESM 直接上生产通常不合适。所以面试别说成「Vite 全面替代打包」，要说「开发按需编译，生产仍打包优化」。

**一句话总结：**

> 开发：原生 ESM 按需编译 + esbuild 预构建依赖 → HMR 轻；生产：Rollup 打包优化体积与请求。

---

## 核心原理

### 1. 为什么「快」要拆场景

| 场景 | 优化目标 | Vite 策略 |
| --- | --- | --- |
| 开发 | 冷启动、HMR、反馈延迟 | 不整包、按需转换 |
| 生产 | 体积、请求数、缓存、执行 | Rollup 打包 + 常规优化 |

混为一谈就会答出「生产也不用打包」这种硬伤。

---

### 2. 对照主链路

**Webpack 开发态（典型心智）：**

```text
启动 → 从 entry 建图 → 转译/打包（范围大）→ 提供 bundle → 改文件 → 再编译相关 chunk
```

**Vite 开发态：**

```text
启动 dev server（几乎不做全量打包）
  → 浏览器 import 源码模块
  → 服务器按路径转换后返回 ESM
  → 依赖走预构建缓存（node_modules/.vite）
  → 改文件 → 精确失效 → HMR / 重新请求模块
```

---

### 3. 三个加速点分别解决什么

| 机制 | 解决什么 | 不管什么 |
| --- | --- | --- |
| 原生 ESM 按需编译 | 启动不必等全量 bundle | 不解决生产海量请求 |
| esbuild 预构建依赖 | CJS 兼容 + 合并碎模块请求 | 不是生产最终打包器 |
| 基于 ESM 的 HMR | 更新链路更短 | 无边界时仍可能整页刷新 |

预构建深挖：[依赖预构建](/md/工程化/Vite/依赖预构建.md)。开发/生产为何两套：[开发与生产差异](/md/工程化/Vite/开发环境与生产环境打包差异.md)。

---

### 4. 为何生产还要打包

即使有 HTTP/2，成百上千模块请求仍有：连接与调度开销、逐模块解析成本、缓存颗粒碎、难做深度 Tree Shaking / 压缩协同。Rollup 擅长 ESM Tree Shaking 与拆 chunk，契合生产目标。

---

### 5. 设计取舍

| 选择 | 得到 | 代价 |
| --- | --- | --- |
| 开发不打包 | 启动与 HMR 快 | 开发行为与生产产物不完全同构，偶发「dev 正常 prod 才爆」 |
| 生产 Rollup | 体积与加载可控 | 生产构建仍随规模变慢，需缓存与 CI 优化 |
| 依赖预构建 | 少请求、可 ESM | 缓存失效、链接依赖、动态 import 要配置心智 |

---

## 常见误区

### ❌ Vite 快是因为生产也用 esbuild 打完所有包

### ✅ 更准确的说法

开发转换/预构建多用 esbuild；**生产默认 Rollup**（压缩等环节另有工具链）。

---

### ❌ Vite 开发完全不编译

### ✅ 更准确的说法

不做全量打包；被请求的 TS/JSX/Vue 等仍会按需转换。

---

### ❌ 有了 Vite 就不再需要理解 Webpack

### ✅ 更准确的说法

存量项目、复杂定制、loader/plugin 生态仍常见；原理可对照学。

---

### ❌ HMR 快 = 永远保留组件状态、永不整页刷新

### ✅ 更准确的说法

取决于是否有热更新边界；没有 accept 会向上冒泡直至刷新。

---

## 高频追问

### Vite 为什么开发环境可以不打包？

现代浏览器支持 ESM，可按 URL 加载模块；dev server 做转换与依赖治理即可。

### 为什么生产还要打包？

控请求数、Tree Shaking、分割、压缩、长期缓存；裸 ESM 源文件数通常过大。

### 依赖预构建解决哪两件事？

CJS/UMD → ESM；碎模块合并，减少请求。

### Webpack 还能比 Vite 快吗？

持久缓存、缩小编译范围、好的分包后，增量构建可以很快；冷启动与默认 HMR 体感 Vite 通常更优。看场景与配置。

### Vite 和 esbuild / Rollup 关系？

esbuild：开发转换与依赖预构建；Rollup：生产打包。Vite 是上层开发服务器与工具链整合。
