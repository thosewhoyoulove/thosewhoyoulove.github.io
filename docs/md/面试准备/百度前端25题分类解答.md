## 一、JSX、浏览器与兼容

### 1. JSX 是什么，为什么采用这种写法，浏览器怎样识别？

JSX 是 JavaScript 的语法扩展，用接近标签的结构描述 UI。它让组件的结构、数据表达式和事件处理放在同一处，通过 `{}` 使用 JavaScript 表达式，减少手写嵌套函数调用的负担。JSX 与 React 是相关但不同的概念；React 可以不使用 JSX，JSX 也可以配置不同运行时。

浏览器通常不直接解析 JSX。构建工具先把 `<h1>{name}</h1>` 转成 JavaScript 调用：自动转换使用 JSX runtime 中的 `jsx` / `jsxs`，经典转换使用 `React.createElement`。运行后得到 React Element，描述类型、props 和子元素；React 再协调 Fiber，由宿主渲染器创建或更新 DOM。React Element、Fiber、DOM 是三类不同对象。

把标签放进 `.js` 并直接交给浏览器，会在解析阶段遇到不支持的语法，而不是自动生成 HTML。采用 JSX 的理由在于声明式组合与 JavaScript 表达能力，不是“浏览器解析 JSX 更快”。参见 [React JSX 文档](https://react.dev/learn/writing-markup-with-jsx)。

原理与执行例子：[React 渲染原理](/md/框架/React/React%20渲染原理.md)。

### 2. 低版本浏览器如何支持新语法？Babel 与 polyfill 有什么区别？

先确定目标版本，再用 Babel、SWC 等工具转换不支持的语法，并补充运行时缺失的 API。Babel 的主链是解析源码得到 AST，插件遍历和改写 AST，再生成目标代码；AST 保存结构和作用域信息，因此不只是字符串替换。

箭头函数是语法，`Promise`、`includes` 是运行时能力。转换箭头函数后，环境仍可能没有 Promise。polyfill 用目标环境可执行的代码实现缺失 API；Babel 可以根据配置引入补丁，但不是所有能力都能补齐。Proxy 无法通过普通 JS 完整模拟，fetch 等 Web API 也要单独评估。

原理、配置与转换过程：[Babel 原理与兼容策略](/md/工程化/体系与实践/Babel原理与兼容策略.md)。

### 3. 浏览器从加载页面到渲染经历什么？

先处理 URL、缓存及可能的 Service Worker，再根据需要解析 DNS、建立连接并发送 HTTP 请求。连接可复用，HTTP/3 基于 QUIC，不能把所有请求都描述成重新建立 TCP。收到 HTML 后，浏览器可以边接收边解析，发现样式、脚本、图片等资源并继续请求。

HTML 形成 DOM，CSS 形成样式规则并参与样式计算；浏览器计算可渲染内容的几何布局，生成绘制记录，经栅格化和合成显示。具体引擎的数据结构有所不同，“DOM + CSSOM → 渲染树”适合作为理解模型。后续修改可能触发样式计算、布局、绘制或合成，不必每次完整重走全部流程。

普通同步脚本可能暂停 HTML 解析；defer 等文档解析完成后按顺序执行，async 下载完成后尽快执行，执行顺序没有同样保证。样式表还可能影响脚本执行和首次呈现。不要把“资源下载”“React 提交 DOM”“浏览器画出像素”当成同一步。

完整链路：[URL 解析流程](/md/网络/URL解析流程.md)、[浏览器渲染原理](/md/浏览器/浏览器的渲染原理.md)。

## 二、React 状态与渲染

### 4. 常见 React Hooks 有哪些？

| Hook | 解决的问题 | 常见选择依据 |
| --- | --- | --- |
| useState | 保存参与渲染的状态 | 数据变化需要更新 UI |
| useReducer | 通过 action 管理状态转移 | 状态分支多、转换规则需要集中 |
| useContext | 读取上层提供的值 | 主题、身份、局部共享依赖 |
| useRef | 保存可变引用 | DOM、计时器 ID；修改 current 不触发渲染 |
| useEffect | 与外部系统同步 | 订阅、连接、需要清理的副作用 |
| useLayoutEffect | 在绘制前同步处理布局 | DOM 测量和必须避免闪烁的调整 |
| useMemo | 复用计算值 | 昂贵纯计算或稳定对象引用 |
| useCallback | 复用函数引用 | 与 memo 子组件或依赖比较配合 |
| useTransition | 标记非紧急状态更新 | 让耗时内容更新可以被紧急输入打断 |
| useDeferredValue | 延后非紧急部分使用的值 | 更新源不由当前组件直接控制 |

Hooks 通常必须在组件或自定义 Hook 顶层按稳定顺序调用，因为 React 需要把本次调用与先前保存的 Hook 状态对应起来。Hook 不是凭名称存状态，自定义 Hook 也只是复用逻辑，每次调用拥有自己的状态。`use` 等特殊 API 的规则需单独看官方定义，不能把例外扩展到 useState 等常见 Hook。

状态队列、闭包与调度：[Hooks](/md/框架/React/Hooks.md)。

### 5. useEffect 的依赖数组为空意味着什么？

`useEffect(setup, [])` 表示这个 Effect 不依赖组件内随渲染变化的值。客户端挂载提交后运行 setup，后续普通重渲染不会因依赖变化重新运行，卸载时执行 cleanup。重新挂载会重新执行，服务端渲染不运行 Effect；启用 Strict Mode 的相应开发检查时，会额外经历 setup → cleanup → setup，验证清理是否正确。

它不应被理解成“整个程序生命周期只运行一次”。如果读取了 props、state 等响应式值却人为写空数组，回调可能保留旧渲染快照，造成陈旧闭包。依赖项用 Object.is 逐项比较；省略依赖参数则在每次相关提交后重新运行。时序参见 [useEffect 文档](https://react.dev/reference/react/useEffect)。

生命周期与示例：[Hooks 的 Effect 部分](/md/框架/React/Hooks.md)。

### 6. useMemo、useCallback、React.memo 分别缓存什么？何时有用？

`useMemo` 复用计算结果，`useCallback` 复用函数引用，`React.memo` 为组件增加 props 比较，让 React 有机会跳过父级更新引起的组件计算。依赖变化时前两者更新缓存；memo 默认按 Object.is 比较各个 prop，属于浅层比较。它们都是性能优化，不能作为业务正确性的保证。

例如父组件输入搜索词时，一个独立大列表也随父级执行。若列表渲染很贵，先用 memo 包装，再保证传入的列表和回调确实稳定，才可能减少无效工作；若每次都传新对象，memo 的比较通常无法跳过。子组件自身 state 或消费的 Context 变化仍可能更新。具体保证见 [memo 文档](https://react.dev/reference/react/memo)。

先用 Profiler 确认耗时，再判断计算量、引用稳定性和比较成本。廉价计算、一直变化的依赖、小组件可能没有收益。useCallback 不会阻止创建函数表达式，也不会自动让函数执行更快；useMemo 应保持纯计算，不能用来发请求。

原理：[Hooks](/md/框架/React/Hooks.md)；memo 与引用示例：[百度面经](/md/面试准备/百度面经.md)。

### 7. Virtual DOM 是什么，React 为什么使用它？Diff 怎样工作？

Virtual DOM 可以先理解成用内存对象描述 UI，让开发者声明状态对应的界面，渲染器再把变化落实到宿主。React Element 是 UI 描述，Fiber 保存运行状态、树关系和待处理工作。它有创建对象和协调成本，不保证比精确手写 DOM 更快；价值还在声明式组合、跨宿主和统一更新模型。

React 协调时，通常在同一父级下按 key 与类型判断旧 Fiber 是否可复用，再根据新 children 构建下一轮工作。列表先顺序匹配，必要时建立剩余旧项的映射；通过旧索引与 lastPlacedIndex 判断是否标记移动。标记发生在 Render，已上屏 DOM 的插入、移动和删除在 Commit 执行。

稳定 key 表示业务身份，不能只为消除警告随机生成。React 的常用同层启发式降低了协调成本，不保证任意树变换都得到最少 DOM 操作。

对象与阶段：[React 渲染原理](/md/框架/React/React%20渲染原理.md)；列表逐步演算：[React Diff 算法](/md/框架/React/React%20Diff算法.md)。

## 三、移动端与跨端

### 8. JSBridge 是什么？H5 怎样调用 Native，Native 怎样返回结果？

JSBridge 是网页与原生宿主间的通信机制及约定。宿主先暴露消息入口，H5 发送 `{ id, method, params }`，Native 校验来源、方法白名单、参数和权限后执行，再返回同一 id 和结果。JS 根据待处理请求表兑现对应 Promise，并清理定时器。

通道可以由注入接口、WebKit 脚本消息等实现。请求 ID 用来处理并发与乱序，超时用来结束等待，版本握手用来识别宿主支持哪些能力。超时不代表原生动作已经取消；页面关闭和迟到响应也必须有明确处理。

双向链路、可运行教学示例：[WebView、JSBridge 与跨端原理](/md/框架/移动端/WebView与JSBridge及跨端原理.md)。

### 9. WebView 是什么？H5 跑在 App 中发生了什么？

WebView 是 App 内的网页容器。Native 创建或复用容器，配置导航与消息通道，再加载 URL 或本地 HTML；网页仍由 Web 引擎执行 JS、解析 DOM/CSS 并绘制。它不会因为装进 App 就自动变成原生视图。

额外问题来自宿主环境：Bridge ready、Cookie 与原生登录态同步、返回栈、键盘、安全区、权限、媒体限制和前后台生命周期。WebView 被复用时还要防止旧页面状态和消息泄漏到新页面。

容器与生命周期：[WebView、JSBridge 与跨端原理](/md/框架/移动端/WebView与JSBridge及跨端原理.md)。

### 10. React Native 与其他跨端框架怎样理解？

先比较渲染目标。WebView H5 主要输出 DOM；React Native 的核心组件对应原生视图；Flutter 主要使用自己的渲染体系绘制 UI。它们都能跨平台复用部分代码，但 Web 代码复用、原生交互、包体积和平台适配成本不同。

React Native 不能只答“JS 通过 JSON Bridge 调 Native”。这是对历史架构的概括；新架构需区分 JSI 的互操作、Fabric 的渲染、TurboModules 的原生模块组织与 Codegen 的接口生成。使用 JavaScript 不代表使用 DOM，也不代表没有平台代码。

方案对比与架构边界：[WebView、JSBridge 与跨端原理](/md/框架/移动端/WebView与JSBridge及跨端原理.md)。

## 四、网络通信与工程化

### 11. HTTP 短轮询、SSE、WebSocket 分别适合什么？

| 方式 | 机制 | 适合场景 | 主要成本 |
| --- | --- | --- | --- |
| 短轮询 | 客户端定时发 HTTP 请求 | 低频状态刷新、部署简单的兜底 | 空请求与更新延迟之间取舍 |
| SSE | HTTP 响应保持打开，服务端发送事件 | 通知、任务进度、文本生成 | 主要单向，需处理代理缓冲与重连 |
| WebSocket | 握手后建立双向消息通道 | 协作、游戏、持续双向交互 | 连接管理、心跳、重连和消息可靠性 |

SSE 的单向指这一响应流的数据方向，客户端仍可另发 HTTP 请求。短轮询也不意味着每次重新建立 TCP，HTTP 连接可以复用。若上下行都持续高频且需要低延迟，WebSocket 更自然；若请求一次、持续接收结果，HTTP 流式响应往往足够。

详细选型：[流式渲染与 SSE](/md/Agent/流式渲染与SSE.md)、[WebSocket](/md/网络/WebSocket.md)。

### 12. 为什么 AI 输出适合 SSE？如何断线补发？

生成内容通常由服务端逐步产生，客户端主要持续接收，SSE 的事件文本格式和 HTTP 基础设施适合这个方向。它改善首个可见内容的等待体验，并不保证模型总生成时间变短。也可以用 fetch 读取遵循 SSE 格式的响应，方便携带 POST 请求体和自定义请求头；这与原生 EventSource 的 API 能力不同。

断线恢复应保存 `runId + eventId`。服务端先记录可重放的增量，再发送；客户端重连时携带游标，服务端重放后续事件，客户端按序号去重。原生 EventSource 支持自动重连和 Last-Event-ID，但“补发什么”需要服务端保留记录。fetch 读流的重连与游标由应用实现。

例如已收到 1～8，事件 9 发送后断线，客户端以 8 续传；即便再次收到 8，也应忽略，再追加 9。日志过期则返回快照或明确无法续传，不能重新启动一次生成冒充续传。参见 [SSE 协议字段与重连](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)。

解析边界、取消和恢复：[流式渲染与 SSE](/md/Agent/流式渲染与SSE.md)。

### 13. Webpack 原理和完整构建流程是什么？

Webpack 以模块依赖图为基础组织可部署资源。读取并规范化配置后创建 Compiler、注册插件；每次构建创建 Compilation，从 entry 出发解析模块路径，运行 loader 转换源码，解析 import / require 等依赖，再递归收集模块。

随后形成模块与 chunk 的关系，按入口、动态 import、拆包策略等组织产物，并进行相应优化与代码生成，最后输出 assets。Compiler 管长期编译环境，Compilation 管本次构建；module 是图中的模块，chunk 是组织输出的模块集合，asset 是最终资源。插件通过钩子参与这些过程。

`entry → resolve / loader / parser → 依赖图 → chunk → assets` 是主链，不代表每个插件都严格串行执行，也不代表只输出一个 JS 文件。构建概念依据 [Webpack 文档](https://webpack.js.org/concepts/)。

构建 Trace：[Webpack 构建流程](/md/工程化/Webpack/构建流程.md)。

### 14. Loader 与 Plugin 的区别是什么？

Loader 主要处理模块的内容转换，例如把 JSX 转成 JS，或把 CSS 转成后续工具能够处理的模块。Plugin 通过编译生命周期钩子介入模块、chunk、资源和输出，例如生成 HTML、提取资源、统计构建信息。两者的关键区别是作用接口和生命周期，不是单纯看名字里有没有“插件”。

普通 loader 链通常从右到左执行，pitch 阶段另有规则；Plugin 则按所订阅钩子的语义运行，不能套用“统一从右到左”。babel-loader 是 Webpack loader，Babel plugin 是 Babel AST 转换插件，两个 plugin 概念不能混淆。[Compiler hooks](https://webpack.js.org/api/compiler-hooks/) 提供了插件可参与的阶段。

执行顺序与职责：[Loader 与 Plugin](/md/工程化/Webpack/Loader与Plugin.md)、[Loader 执行顺序](/md/工程化/Webpack/Loader执行顺序.md)。

### 19. SSE 流式事件的作用是什么？还有哪些通信方式？

第 11 题关注传输选型，第 12 题关注恢复，这题重点是把字节流变成应用可处理的业务事件。可以约定 `delta`、`tool_start`、`tool_result`、`done` 等事件类型，让客户端区分文本追加、工具状态和终态；这些名称是应用协议，不是 SSE 规定必须使用的事件名。

```text
id: 9
event: delta
data: {"text":"你好"}

```

上面的事件需要空行结束。一次网络 read 不等于一个事件，一个事件也不等于一个 Token。解析器要处理 UTF-8 跨块、多行 data 和尚未结束的事件；前端不能对每个字节块直接 JSON.parse。

其他方式包括长轮询、WebSocket、普通 HTTP 分块或 fetch 流；WebRTC DataChannel 适合特定实时或点对点场景。长轮询是等到有数据或超时再响应，区别于固定间隔马上返回的短轮询；SSE 则定义了文本事件格式与重连相关字段。

传输与应用事件：[流式渲染与 SSE](/md/Agent/流式渲染与SSE.md)。

## 五、Agent 与知识检索

### 15. Skills、MCP、A2A 有什么区别？

Skill 组织可复用任务知识，说明一类任务怎样做；MCP 规范宿主发现和使用工具、资源与提示模板；A2A 关注独立 Agent 之间的能力发现、任务交接、状态和产物。

例如加载“故障诊断” Skill，通过 MCP 查日志，再把保修判断委派给另一个 Agent。三者可以组合，但加载说明文档不代表已执行工具，工具接入也不代表拥有所有业务权限。同进程多 Agent 可以直接调用，不必为了“多 Agent”而引入 A2A。

分层、协议与例子：[Skills、MCP 与 A2A 的区别](/md/Agent/Skills与MCP及A2A的区别.md)。

### 16. Harness 工程是什么？怎样让 AI 按指定工作流执行？

Harness 是围绕 Agent 的运行、控制和反馈系统，承载上下文、工具、权限、状态、预算、恢复与验收。若业务要求“先检索，再草拟，再校验”，应把合法阶段和转移条件放进运行时状态机，而不是只在 Prompt 里写“必须遵守”。

运行时按阶段限制工具，验证每一步产物，失败时有限重试，持久化任务状态和产物引用；外部写入要考虑幂等和已有授权。模型可以选择查询词或组织报告，但不能跳过权限校验或自行宣告验收通过。用成功率、违规率、耗时和成本衡量改善。

工作流和失败 Trace：[Agent 与 Skill 体系](/md/Agent/Agent与Skill体系.md)；岗位背景：[DuMate、千帆与 Harness 工程](/md/面试准备/技术/DuMate千帆与Harness工程.md)。

### 17. Agent 上下文怎么提供？一次给太多信息怎么办？

由宿主或服务端组织当前请求：固定约束、用户目标、任务状态、历史消息、工具描述、检索证据和工具结果。数据库保存了内容，不代表本次请求自动携带；即使存在会话机制，进入模型的内容仍受上下文窗口和预算限制。

先为输出和安全余量留空间，再按优先级组织输入。固定约束、精确 ID、已确认参数保留；旧对话摘要；工具大结果存文件和引用；资料按问题检索；无关 Skill 不加载。全文综合可分段处理再汇总，但要保留统一字段和来源，避免摘要误丢否定条件。

分层策略与预算演算：[上下文与 Token 体验](/md/Agent/上下文与Token体验.md)。

### 18. Skill 怎样按需加载和组合？

先加载名称与描述等元数据来发现候选，匹配任务后读取选中 Skill 的正文，执行到具体步骤时再读参考材料或运行脚本。这样减少无关上下文；路由、缓存和版本失效由宿主实现，不能假定模型天然知道所有 Skill。

组合时按产物契约衔接：检索 Skill 输出证据，写作 Skill 输出带引用草稿，校验 Skill 检查草稿和证据。相互依赖的步骤串行，独立读取可以并行。冲突由宿主的指令优先级和权限规则裁决，并设置最大修订次数，避免两个 Skill 互相反复修改。

加载链路与组合 Trace：[Skills、MCP 与 A2A 的区别](/md/Agent/Skills与MCP及A2A的区别.md)。

### 20. 什么是 RAG 多路召回？

RAG 在生成前检索外部证据。多路召回让不同策略互补，例如关键词召回擅长错误码和型号，向量召回擅长同义表达，也可以加入不同数据源或查询改写结果。

结果先按稳定片段 ID 去重，再融合排名，必要时重排。关键词与向量原始分数尺度不同，不能未经处理直接相加；RRF 按排名贡献合并，是一种可解释的融合方式。重排只能调整已召回候选，无法凭空补回漏掉的证据。

RRF 数值演算、分片与重排：[RAG 索引与多路召回](/md/Agent/RAG索引与多路召回.md)。

### 21. RAG 为什么要建索引？为什么不每次扫描全部知识库？

倒排索引预先保存“词 → 片段列表”，向量索引则组织语义向量，减少大库反复逐条比较的成本。它们用存储和更新维护换查询效率；数据小、并发低或过滤后候选很少时，精确全量搜索完全可以合理使用。

把所有原文发给模型又是另一种成本：Token、延迟、窗口上限、无关噪声和越权风险。索引不会自动保证正确或权限安全，还要维护版本、删除、缓存失效和访问控制。近似向量检索可能漏召回，应按规模和效果选择。

索引原理与适用范围：[RAG 索引与多路召回](/md/Agent/RAG索引与多路召回.md)。

### 22. 除了提问式对话，Agent 还有什么形态？

可以是后台执行任务并交付报告的任务 Agent、由告警或工单触发的事件 Agent、定时巡检 Agent、编辑器或画布内的嵌入式助手，以及结合图像和语音的操作助手。核心区别在目标、工具选择和反馈闭环，聊天框只是入口之一。

产品上应按产物设计界面：后台任务需要进度、取消与恢复；事件任务需要通知去重；文档修改需要差异与确认；多模态操作需要执行轨迹。固定规则的定时脚本也可能已经满足需求，不必所有自动化都交给模型。

形态与运行要求：[Agent 与 Skill 体系](/md/Agent/Agent与Skill体系.md)、[人机协同与主动式交互](/md/Agent/人机协同与主动式交互.md)。

## 六、树与遍历

### 23. 二叉树前序、中序、后序、层序分别是什么？

前序根左右，中序左根右，后序左右根；三者都是 DFS，只是处理当前节点的时机不同。层序按深度从小到大，同层通常从左到右。访问不是“函数第一次进入”，而是记录值或执行目标动作。

对根 A、左 B、右 C 的树，结果分别为 ABC、BAC、BCA；层序为 `[[A], [B, C]]`。中序对一般二叉树不保证排序，只有满足相应约束的二叉搜索树才有顺序性质。

完整树例子与实现：[二叉树遍历与 DFS、BFS](/md/算法/二叉树遍历与DFS及BFS.md)。

### 24. 为什么 DFS 常用栈或递归，BFS 常用队列？

DFS 需要先深入最新发现的分支，后进先出的栈保存尚未完成的路径。递归使用隐式调用栈，所以不是独立于栈的另一种机制。显式栈可以避免引擎递归深度限制；先序要先压右再压左，才能先弹出左孩子。

BFS 要先完成早已发现的浅层节点，先进先出的队列符合这个顺序。遍历通常都为 O(n) 时间，DFS 辅助空间看树高 O(h)，BFS 看前沿宽度 O(w)；包含结果数组时，还要计入 O(n) 输出空间。

栈和层前沿演算：[二叉树遍历与 DFS、BFS](/md/算法/二叉树遍历与DFS及BFS.md)。

### 25. 怎样实现二叉树层序遍历？

空树返回空数组。把根作为第一层，用 current 保存当前层，遍历时收集本层值，并把非空左右孩子写到 next。处理完本层才令 current = next，直到没有下一层。

这个按层队列实现不会把刚加入的孩子混进本层，也避免反复 shift 的元素搬移。每个节点访问一次；辅助空间与最大宽度同阶，结果空间为 O(n)。使用单数组加 head 时，如果不释放历史元素，存储可能达到 O(n)，空间分析要跟着实际实现走。

可直接练习的 `levelOrder` 代码及边界：[二叉树遍历与 DFS、BFS](/md/算法/二叉树遍历与DFS及BFS.md)。
