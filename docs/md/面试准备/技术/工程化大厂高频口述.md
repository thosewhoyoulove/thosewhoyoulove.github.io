# 工程化大厂高频口述

面向社招（约 2～5 年）**中大厂一面/二面**常见工程化题。每题给可直接说的口述稿；深挖链路点右侧深文。不保证某司原题，但覆盖字节 / 阿里 / 百度 / 美团 / 腾讯等场次里反复出现的问法。

**用法：** 先按顺序把 1～10 各说一遍（每题约 1 分钟）；再看「加分追问」能不能接住。

---

## 1. 你怎么理解前端工程化？

> 工程化不是装 Webpack 或 Vite，而是用规范、工具和流程，把多人协作里容易出错、难重复的事变成可重复交付。我会分几层：开发要启动快、规范统一、提交前拦住低级问题；构建要产物正确、体积和缓存可控；质量靠 lint、类型、测试和 CI 前置；发布要环境隔离、可灰度、可回滚；线上要有监控和复盘。目标是问题尽早暴露，发布可追踪。小项目做轻量版就行，大项目再按痛点加 Monorepo、完整测试和精细监控，不为堆工具。

**深文：** [工程化体系](/md/工程化/体系与实践/工程化体系.md)

**常追问：** 你在项目里落地过哪两件？用什么指标证明有效？

---

## 2. Vite 为什么快？生产还要打包吗？

> 快主要在开发。传统 Webpack 开发常要先从入口建依赖图再打包，项目越大冷启动越慢。Vite 开发用浏览器原生 ESM，dev server 起来很快，浏览器要哪个模块才按需转换哪个；第三方依赖用 esbuild 预构建，解决 CJS 兼容，并把碎模块合并，减少请求。HMR 也是主要重拉变更模块，不必整包重打。生产仍然用 Rollup 打包，因为线上要控制请求数、做 Tree Shaking、分割和压缩；源码直接 ESM 上生产，文件太多，优化也不够。

**深文：** [为什么 Vite 快](/md/工程化/Vite/为什么Vite快.md)、[开发生产差异](/md/工程化/Vite/开发环境与生产环境打包差异.md)

**常追问：** 预构建缓存在哪、何时失效？esbuild 和 Rollup 各负责什么？

---

## 3. 依赖预构建解决什么问题？

> 两个问题。一是兼容：开发按 ESM 走，很多 npm 包仍是 CJS/UMD，要先转成浏览器能 import 的 ESM。二是性能：像 lodash-es 内部文件极多，一个 import 可能打出几百请求，预构建会合并成更少模块。结果缓存在 `node_modules/.vite`，lockfile 或相关配置变了会重建，不行就 `--force`。注意它主要服务开发，不是生产打包本身。

**深文：** [依赖预构建](/md/工程化/Vite/依赖预构建.md)

---

## 4. Webpack 构建流程讲一下

> 从 entry 递归建模块依赖图，再输出 chunk/assets。先读配置创建 Compiler、注册 plugin；每次构建有 Compilation。对模块：resolve → loader 转换 → parser 找依赖，收成 ModuleGraph，再按入口、动态 import、splitChunks 生成 ChunkGraph；优化阶段做摇树、压缩等，最后 emit 到磁盘。Plugin 通过钩子插在这些阶段上。

**深文：** [构建流程](/md/工程化/Webpack/构建流程.md)

**常追问：** Compiler 和 Compilation 区别？动态 import 在图里意味着什么？

---

## 5. Loader 和 Plugin 区别？

> Loader 管单个模块怎么变成 Webpack 能处理的内容，比如 TS、Less、图片；常组成链，顺序要配对。Plugin 管整次构建，在生命周期钩子里改 compilation，比如生成 HTML、压缩、分析包体、上传。一句话：loader 是模块转换器，plugin 是流程扩展点。CSS 抽离这类常两者配合。

**深文：** [Loader 与 Plugin](/md/工程化/Webpack/Loader与Plugin.md)

**常追问：** loader 能代替 plugin 吗？babel-loader 和 Babel plugin 别混。

---

## 6. 包体积大了怎么优化？（大厂极爱）

> 先分清是构建慢还是产物大还是线上加载慢，用 analyzer、Network、Lighthouse 看数据。体积侧：确认 Tree Shaking 是否生效，去掉 CJS/副作用坑；路由和重型组件懒加载；vendor 按变化频率拆，避免业务一改就 bust 框架缓存；压缩和图片/字体策略。加载侧：控制首屏 JS、关键资源优先级、HTTP 缓存与 CDN。每改一项要对着主包体积、LCP、瀑布图看有没有用，避免无脑越拆越碎。

**深文：** [打包优化](/md/工程化/体系与实践/打包优化面试专题.md)、[分包](/md/工程化/构建优化/分包策略.md)、[Tree Shaking](/md/工程化/构建优化/TreeShaking原理.md)

**常追问：** 如何证明优化有效？拆太细有什么坏处？

## 7. Tree Shaking 原理？为什么摇不掉？

> 本质是删掉没被用到的导出，依赖 ESM 静态结构，编译期能分析 import/export。打包器标记 used，再在优化和压缩阶段删死代码。它不是压缩本身：压缩是把剩下的写短。摇不掉常见原因：依赖是 CJS、模块有副作用却乱标 `sideEffects: false`、Babel 提前把 ESM 转成 require、或者用了通配/动态访问导出。

**深文：** [Tree Shaking](/md/工程化/构建优化/TreeShaking原理.md)

---

## 8. 分包策略怎么定？

> 目标是首屏更小、缓存更稳，不是 chunk 越多越好。路由动态 import 拆非首屏；React/Vue/图表等稳定依赖单独 vendor；共享业务抽 common；大编辑器类组件懒加载。拆完看首屏 JS、LCP、缓存命中和路由切换耗时。过细会增加请求和解析调度；HTTP/2 只能缓解一部分。

**深文：** [分包策略](/md/工程化/构建优化/分包策略.md)

---

## 9. 前端 CI/CD 你怎么设计？

> CI 把检查前置：按 lockfile 安装 → lint/类型 → 测试 → 生产构建，失败就不能合主分支。CD 把同一份制品部署到预览/预发/生产，生产变更可追溯，出问题回滚上一制品，而不是「再点一次不确定的构建」。前端还要注意静态资源 hash、`index.html` 短缓存、Node 版本一致。灰度是发布策略，和流水线骨架一起说更完整。

**深文：** [CI/CD](/md/工程化/体系与实践/CI&CD.md)

**常追问：** CI 太慢怎么办？密钥怎么管？

---

## 10. Monorepo 什么时候用？

> 多个应用强共享组件库、工具库、类型，跨仓改不动时适合 Monorepo。pnpm workspace 管包和本地链接；Turborepo/Nx 管任务编排、缓存和只跑受影响包，否则仓一大 CI 会炸。项目独立、权限隔离强就用 MultiRepo 更简单。关键是包边界，别让业务代码互相穿透。

**深文：** [Monorepo](/md/工程化/体系与实践/Monorepo.md)

## 加分题（大厂二面常顺手问）

### A. 构建突然变慢，你怎么查？

> 先对比是冷构建还是增量；看 CI 还是本地；用速度分析看 loader/plugin 耗时；查缓存是否失效、编译范围是否被误扩大、依赖是否暴增。优化方向是持久缓存、缩小 include、换更快转换器、Monorepo 下只构建 affected。

### B. 发版后用户还是旧资源 / 白屏？

> 查 CDN 与浏览器缓存：JS/CSS 是否 contenthash；`index.html` 是否被长缓存；发布是否先上传资源再更新 HTML；回滚是否切到完整旧制品。白屏还要看监控里的 chunk 404、兼容性与错误栈。

### C. HMR 和 Live Reload 区别？Vite HMR 为何快？

> Live Reload 整页刷；HMR 尽量只换模块并保留状态。Vite 开发不整包，变更后主要重请求相关 ESM，所以体感更快；没有热更新边界仍可能整页刷新。

**深文：** [HMR](/md/工程化/构建优化/HMR热更新原理.md)

### D. 工程化和性能优化什么关系？

> 工程化保证能稳定产出可发布包；性能优化关注用户侧 LCP、卡顿等。分包、压缩、缓存既是工程手段也是性能手段。面试里先说清问题是「构建慢」还是「页面慢」，再选题。

**深文：** [前端性能优化速记](/md/面试准备/技术/前端性能优化.md)

## 项目怎么接（大厂很看重）

每题尽量落到：

```text
现象（启动 40s / 主包 2MB / 发版回滚靠人肉）
  → 定位（analyzer / 瀑布图 / CI 耗时）
  → 动作（预构建/懒加载/splitChunks/流水线卡点）
  → 数字（耗时、体积、LCP）
  → 取舍（过细分包、缓存复杂度）
```

没有真实数字就说量级和对比，不要编精确假数据。
